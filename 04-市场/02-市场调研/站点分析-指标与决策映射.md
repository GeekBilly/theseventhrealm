## 一、数据源的三次校准（2026-09-30 实测，读文档前必看）

原计划走 Cloudflare Web Analytics，实测发现走不通，连退两步才落地。**这三条决定了数据能信到什么程度。**

| # | 原假设 | 实测结果 | 处置 |
|---|---|---|---|
| 1 | Web Analytics 走 **Analytics Engine SQL API** | 返回 **403 `Authorization error`**，连 `SHOW TABLES` 都不行。Token 有 `Account Analytics:Read`、账号也对、状态 active。Cloudflare 社区 2026-09-08 有完全相同的报告，**连后台 Studio 都 403** | 判定为 **Cloudflare 侧问题**，不是我们的操作问题 → 换通道 |
| 2 | 退到 **GraphQL Analytics API** 找 Web Analytics | 全量 introspect 了 **2045 个类型**，**没有任何 webAnalytics / pageView 类型**，只有 RUM（Browser Insights，另一个产品，没开） | Web Analytics **当前无公开 API** |
| 3 | —— | 最终取 **Zone Analytics**（`httpRequestsAdaptiveGroups`）：有 `visits`（按 IP + 30 分钟不活动去重）、页面 / 国家 / 设备维度 | **可用**，但三个限制见下 |

### 三个必须记住的限制

1. **它数的是请求，不是人。** 免费版拿不到 `botManagementDecision` / `clientRefererHost`（返回 "does not have access"），所以**无法精确识别爬虫，也读不出来源渠道**。
   → 脚本按路径规则过滤：`wp-login` / `xmlrpc` / `wp-includes` / 带 `.php` `.xml` `.json` 等扩展名 / `//` 前缀。
2. **噪声约 77%。** 首采数据：窗口内真实访次 838，爬虫+系统 2904。最大噪声源是 `/wp-login.php`（1699 次，**单页超过首页**）——典型的撞库扫描。
   → **绝对不要拿未过滤的总量做决策**。看板里的「真实访次」已过滤。
3. **只能回溯 3–4 天。** 查 9-27 之前的任何区间都返回 0 行。
   → **每日采集不是优化，是唯一能积累趋势的办法**，断一天就永久缺一天。已并入每日晨检。

## 二、六个指标，各自回答一个问题、触发一个动作

| # | 指标 | 频率 | 回答什么 | **触发规则（预先写死）** |
|---|---|---|---|---|
| 1 | **真实访次趋势**（日/周） | 周 | 整体有没有真的动起来 | 连续 **3 周**周环比零增长 → **换钩子方向**，不是加发布频次（加频次只会耗尽时间预算） |
| 2 | **Top 落地页**（内容页 Top 10） | 周 | 哪个内容真的被需要 | 某朝代页连续 **2 周**进 Top3 → 优先给它出成品图/视频；若它同时是主要入口 → **M6（16 朝页换厚内容）就从这一页开始做** |
| 3 | ~~来源域名 / UTM~~ | — | — | ⛔ **免费版拿不到**（`clientRefererHost` 无权限）。**暂以「发布日 vs 次日访客增量」这个交叉指标替代**（见下）——它能间接回答"哪个渠道有用" |
| 4 | **国家 / 地区** | 月 | 中文 vs 英文内容的优先级 | 非中国大陆占比 >30% → 重估海外线；但**"可以用海外"不等于"可以用非法定信道"**（R-37b 不因数据好看而松动） |
| 5 | **设备**（桌面/移动/平板） | 月 | 出什么尺寸的图 | 移动端 >60% → 竖版优先、金句线排产靠前；否则桌面横版优先。**当前 97% 桌面 / 3% 移动**（样本小，仅供参考） |
| 6 | **噪声占比** | 月 | 站点有没有被盯上 | 噪声 >85% 或 `/wp-login.php` 单日 >3000 → 属于**安全风险不是增长问题**，转 `11-运营/风险管控`，考虑上 CF 免费 WAF 规则/限速 |

### 一个交叉指标，最能说明问题

**发布日 vs 次日访客增量** —— 把 `发布数据.csv`（我发了什么）和 `站点数据.csv`（来了多少人）按天对齐。
它回答一个靠单看一边永远答不了的问题：

> 我们发的内容是**有效钩子**，还是**自嗨**？

判据：发布后次日**真实访次**增量 <20% 且连续 5 条如此 → 钩子方向不对，回去改内容，不要加大投产量。

> 这也是指标 3 缺失后的**替代方案**：与其知道"从哪个域名来"（拿不到），不如知道"发完有没有涨"（拿得到）。

## 三、三条我们先想清楚的事（避免数据一到手就跑偏）

1. **不要提前下结论**：站才上线 5 天，真实访次基线约 **200/日**（含噪声口径则上千）。
   **比率指标会剧烈跳动**，前 4 周只看**趋势方向**，不看绝对值。
2. **不要拿未过滤的总量说事**：撞库扫描能把总量放大 4 倍。对外/对内引用一律用 `visits_clean`。
3. **不要派生新数据源**：不上 GA（Cookie 横幅会把"无 Cookie"这个卖点做掉）。
   数据不够用就加维度，不要加工具。若将来 Cloudflare 修好 SQL API，可升级到 Web Analytics 口径。

重新生成时：Cloudflare 后台 → My Profile → API Tokens → Create Custom Token
→ 权限只需 **`Account` › `Account Analytics` › `Read`**（官方文档口径，最少权限即可）

security add-generic-password -a theseventhrealm -s cf-web-analytics -U -w "<你的 token>"
