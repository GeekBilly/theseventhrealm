## 一、先说三句话

1. **有一件事正在把你所有的 SEO 努力归零**：百度爬虫被 Cloudflare 在边缘直接 403 拦截。
2. **资产本身非常强**：16 卷长文、9.5 万字、191 种典籍引注——这在搜索引擎眼里是稀缺的高质量原创。**问题不在内容，在于内容从没被"翻译"成搜索引擎听得懂的语言。**
3. **好消息：最贵的问题解起来最便宜。** 只要给 17 个页面各写一条摘要，meta description 就自动修好，**一行主题代码都不用改**（原因见 §三）。

## 二、体检结果（实测）

### 2.1  crawler 可达性 —— **这是唯一的硬伤**

| 爬虫 | 结果 | 判定 |
|---|---|---|
| **Baiduspider** | **HTTP 403** `Your request was blocked.`（`server: cloudflare`） | 🔴 **致命：国内最大搜索入口零收录** |
| Googlebot | HTTP 200 | ✅ 可正常抓取 |
| bingbot | HTTP 200 | ✅ 可正常抓取 |

**两层封锁，必须都解除**（只改一层没用）：

| 层 | 现状 | 在哪改 |
|---|---|---|
| ① **robots.txt**（君子协定） | `User-agent: Baiduspider → Disallow: /` | Cloudflare 后台托管的 robots.txt |
| ② **WAF 边缘拦截**（实打实） | 即使 robots 允许，仍会 403 | Cloudflare 安全策略（Bot Fight / WAF 自定义规则） |

> 证据：`cf-ray: a42fdc88af99e3a4-SEA`、`content-type: text/plain`、响应体 25 字节 —— 典型 Cloudflare 边缘拒绝，不是 WordPress 也不是 GoDaddy。

#### 2.1.1 根因已定位（2026-09-30 复核）——**不是你的配置，是 Cloudflare 把百度改了类**

把线上 robots.txt 全文拉下来逐行看，`Baiduspider` 那两行**夹在 Cloudflare 托管段里面**：

```
 80| User-agent: Baiduspider      ← 在托管段内（第 27 行 BEGIN、第 129 行 END 之间）
 81| Disallow: /
```

而 Cloudflare 官方 ⟨robots.txt setting⟩ 文档（2026-08-03 版）列出的托管列表是
`Amazonbot / Applebot-Extended / Bytespider / CCBot / ClaudeBot / Google-Extended / GPTBot / meta-externalagent` ——**里面根本没有 Baiduspider**。

**结论：Cloudflare 近期把 `Baiduspider` 划进了「训练类爬虫」**，于是两件事同时发生：
① 托管 robots.txt 里被自动加了一条 `Disallow: /`；
② AI Crawl Control 对「训练类」默认 Block → 边缘直接 403。

**这解释了两件事**：为什么只有 `Baiduspider` 这一个裸 UA 被拦（`-image` / `-mobile` / `-render` 都没被打上训练标签）；也说明**这不需要动任何整体安全策略**，只需把这一类里的这一个 UA 单独放行。

> 顺带排除一个变量：`Bot fight mode` 当前是**关闭**状态，所以 403 不是它造成的，不用去开它。

顺带一提：robots.txt 里还禁了 **GPTBot / ClaudeBot / CCBot / Perplexity 类爬虫**（连同 `Content-Signal: ai-train=no`）。
这是** intentional 的选择**，我不擅自改——但它意味着你放弃了「AI 搜索引用」这个增量入口，见 §五·权衡题。

## 三、一个决定行动路径的技术发现

读子主题 `functions.php` 第 95 行：

```php
$raw = $post->post_excerpt ? $post->post_excerpt : $post->post_content;
```

> **只要页面有「摘要」（`post_excerpt`），就用它；没有才回退到正文截断。**

这意味着：**给 17 个页面各写一条摘要 → meta description / og:description / twitter:description 三处同时自动变好，零主题改动。**

对比一下难度：

按项目规矩（主题包上传是稀缺操作数），**后三项攒一批一起传**，第一项现在就能做。

> ⚠️ **这条不要再引到需要跨境信道的方案上去。** Google 侧的正确姿势是「优化 + 等它自己来爬」，**不要为了看 GSC 数据去开任何东西**——那是 R-20 原样重演。

### 权衡题（要你决定，我不替你决定）

robots.txt 里 `GPTBot / ClaudeBot / CCBot / Google-Extended` 全被 Disallow。

- **保持现状** = 保护内容不被抓去训练 AI，**但放弃了被 AI 搜索（Perplexity / DeepSeek / ChatGPT Search）引用的入口**
- **部分放开** = 争取 AI 时代的推荐流量，但内容会被用于 AI 训练

这是「短期保护 vs 长期可见性」的取舍，跟海外线一样属于策略判断。**建议先不动**——等百度主战场跑起来再说，变量不要一次加两个。

> **⚠️ 2026-09-30 更新：这道题已经不是"要不要做"，而是"必须一起做"。**
> 后台实景确认：`Baiduspider` 被 Cloudflare 归入 **Training（训练类）** 这一档，
> 而解 403 的唯一开关就是 **`Training: Block → Allow`** —— 类别级，**做不到只放行百度一个**。
> 所以「放行 AI 训练爬虫」是解封百度的**附带代价**，不是可选项。
> 判断与恢复精细控制的办法见 §六 P0「副作用与恢复精细控制」。结论仍是：**现在就换**（百度是致命项，且完全可逆）。

## 十、常驻运维口径（2026-09-30 自 MEMORY.md 下沉）

> `MEMORY.md` 每次会话整段注入、**超 8000 字符即被截断**，故这五条的完整口径放这里。
> 上面各章是「为什么」，本节是「以后每次都要照做的」。

**① 百度被 Cloudflare 封：类别级开关，改一个不够**

- 位置：CF `Security → Bot traffic → Configure AI bot policies`
- `Training: Block` → **改成 `Allow (do not block)`**
- `Enable Bot Preference Sync`（开着会把 CF 的配置前置进你的 `robots.txt`）→ **关掉**
- **两条必须同时改**：只改 Training → robots.txt 里仍写着禁止抓取，百度照做；只关 Sync → 边缘照样 403，蜘蛛连门都摸不到
- **即时生效，不必 Purge 缓存**。复核脚本：`11-运营/scripts/check-crawler-access.py`
- 副作用：`Training` 是**类别级**，做不到只放行百度一个 → 见 §五「权衡题」

**② 元信息：写 `post_excerpt` 就自动修三处 description**

- 子主题 `seventhrealm-root/functions.php` L95 有钩子：**页面有 `post_excerpt` 就用它，没有才回退正文截断**
- 所以修 description 的**唯一正确入口是填「摘要」**，不需要改主题
- ⚠️ 坑：**REST 不返回 `excerpt.raw`**，只能读 `excerpt.rendered` 再去标签
- 批量脚本：`11-运营/scripts/set-seo-excerpts.py --check` → `--apply`（自动备份 + 复读校验）

**③ 交百度的 sitemap 只认扁平版**

- 用 `03-页面/站点文件/sitemap-baidu.xml`，生成器 `11-运营/scripts/build-baidu-sitemap.py`
- **不能交 `wp-sitemap.xml`** —— 索引型（sitemap index）百度不受理
- **内容一变就要重跑 + 重传**，否则百度读到的是旧结构
- 提交主路径＝百度搜索资源平台的 **「API 提交」tab**（已打通：token 在钥匙串服务名 `baidu-ziyuan-push`；脚本 `baidu-push.py` + `baidu-push-auth.sh`）

**④ 不许假定 sitemap 入口会自动恢复**

- 该入口实测为 `disabled` 状态；**站点无备案 + 新站**，不要假定平台会自动放开

**⑤ 两个「绝不」**
