# 第七境 · MVP 变现路线调研（2026-10-02）

> **方法**：5 条候选路线并行调研（agent team，各带网络检索核实 2026 年现状），每条路线按同一组问题作答：启动成本 / 是否需要注册主体 / 身份暴露度 / 是否需要跨境网络 / R-19 判定 / 第一笔收入怎么来 / 致命阻塞。
> **目的**：找出**在不能注册主体、不能用跨境信道、预算每月几十到一两百元**的前提下，跑通「第一笔真实收入」的最短路径。
> **状态**：待用户选择方向。

---

## 一、先说六条硬事实（不好听，但决定一切）

| # | 事实 | 意味着 |
|---|---|---|
| **1** | **几乎所有能收钱的通道都要身份证实名 + 绑定本人银行卡** | R-19 **无法靠选通道规避**。能选的只是**暴露层级**，不是"有无违规" |
| **2** | 🔴 **2025-10 起，平台按季向税务报送个人经营者信息**（税总 2025 年第 15 号公告）：姓名、证件号、地址、店铺名、收入总额/退款/净额/订单数，**境内平台无小额豁免** | 项目原有假设「**收入不公开可查**」**已经失效**。准确表述变成：**公众不可查，税务必然可见** |
| **3** | 个体**免于工商登记**的「零星小额」= **年交易额 10 万元**（《网络交易监督管理办法》第 8 条） | 只要年入 ≤10 万，可以**不注册任何主体**；但**免登记 ≠ 免税**，个税仍要走年度汇算 |
| **4** | 🔴 **个人收款码用于经营收款是违法的**（《银发〔2021〕259 号》，2022-03-01 施行） | **不能**在站上贴个人微信/支付宝收款码卖货。必须走持牌第三方通道 |
| **5** | **所有境外平台都是死路**：Gumroad / Paddle / Lemon Squeezy / Payhip / Ko-fi / Etsy 全部需要**长期稳定的跨境网络** | 撞项目既有约束 43（不得为经营性活动使用非法定跨境信道）**直接排除**。且 Etsy 2026 年中国大陆已不能新开店 |
| **6** | **瓶颈从来不是渠道，是流量与信任状**（名单 0、品牌号 0 粉） | 换任何货架都不产生订单。**渠道方案单独拿出来都是空转** |

> **一句话总结**：这次调研最重要的发现**不是"哪条路能赚钱"，而是"路本身不缺，缺的是人到店门口"**。
> 而 R-19 的真实形态是：**低金额 + 品牌号 + 不注册主体 + 不公开宣传经营身份**，可以把风险压到"低但非零"，压不到"无"。

## 二、五条路线速览

| 路线 | 分 | 能否拿到第一笔 | 成本 | 致命问题 |
|---|---|---|---|---|
| **A 自建站直卖** | **7** | ✅ **3–7 天** | **¥0** | 不解决获客，渠道顺也不出单 |
| **C 国内内容平台** | **6** | ✅ **1–14 天** | ¥0 | 能无门槛收钱的三条路，客单只有 **¥1–39** |
| **D 众筹 / 预售** | **5** | ⚠️ 数月 | ¥0 | 名单 0 时开众筹 = **公开留档的一次性失败** |
| **B 做 App 上架** | **4** | ❌ 6–10 周 | ¥688+ | **Apple 明文封杀壁纸类目** |
| **E 实体周边** | **3** | ❌ | ¥500+ | R-19 下「实体贸易」**最难辩解** |

### 每条的关键情报

**A · 自建站直卖（最优）**
- 国内通道费率：**面包多Pay 2% + ¥0.1/笔**（最低，且**唯一能嵌进自己站内**收款）→ 面包多 5.7% → 爱发电 6% → 知识星球 10–20% → 小报童 21%+
- **全部不要营业执照**，只要身份证 + 银行卡
- ⚠️ 面包多Pay 官方自述「2022 年后停止推广、审核更严」，**有被拒风险**
- ⚠️ 爱发电/小报童有**公开创作者页**；面包多Pay 没有 → **面包多Pay 暴露最低**

**C · 国内内容平台（门槛比想象的高）**
- 🔴 **小红书个人店已对 0 粉新号关闭**：需入驻 >180 天 + 笔记 >30 篇 + **粉丝 >1000** + **近 12 个月任一自然月流水 >6000 元**
- 🔴 **微信小店只收企业店/个体户店**，个人身份证开不了 → 与 R-19 冲突，出局
- 🔴 抖音个人店可开，但**虚拟充值类目不准入** + **禁止贴微信/二维码导流**（会切断回自己站的路）
- ✅ **无门槛能立刻收钱的三条**：**公众号赞赏**（发 3 篇原创即可，0 粉门槛，3–7 天到账）、**闲鱼**（0 保证金、0 粉，3–14 天）、**自有站收款码**（须走第三方通道）

**D · 众筹 / 预售（数据要修正）**
- ✅ **摩点个人可以发起，不需要营业执照**（官方《项目规范》：18+、中国公民、本人收款账户）
- 🔴 但有两条硬红线：**不得为网站类型项目**；**已在中国大陆其他相似平台上线的项目将无法过审**（=事实独家，与站内直卖/小红书冲突）
- 🔴 项目页**公开永久留存**（含未达标百分比）
- 🔴 **项目文档引用的"成功率 78.55%"已核实为《出版人》2021-03 数据**，且发起主体 ~75% 是出版机构，**作者自主发起仅 8.52%（27 项）** → **不能用来支撑 2026 决策**
- 淘宝众筹（造点新货）**强制营业执照** → 出局

**B · 做 App（最被高估的一条）**
- 🔴 **Apple 2026-06-09 更新审核指南 4.3(b)，原文点名 wallpaper**（与约会、手电筒并列）为饱和类目：*"we will not accept new submissions unless they offer a meaningfully different or improved experience"*，并保留下架存量 App 的权利 → **iOS 主路已被官方定向关闭**
- 🔴 **Apple 个人账号会在 App Store 商品页公开显示开发者真实姓名** → 与 R-19「收入不宜公开可查」正面冲突
- 🔴 收款首次 >$5000 触发银行**国际收支申报**；另有每年 5 万美元结汇额度
- 🔴 国内安卓商店（华为/小米/OPPO/vivo/应用宝）普遍要**软著 + 营业执照** → R-19 出局
- ✅ **唯一的活口**：**微信小程序 · 个人主体 · 虚拟支付**（2026-08 新开放）：只要身份证 + 「工具」类目 + 备案，**Android 费率 1% / iOS 12%**，月支付限额 10 万，不需执照
- ⚠️ 但卡在一个**未核实**的前提上：**壁纸内容能否按「工具」类目过审**。这个前提不成立，整条路线归零

**E · 实体周边（最不该现在做）**
- ✅ 淘宝个人店 0 元开店、身份证 + 人脸即可、年 ≤10 万免登记
- 🔴 **R-19 下最难过**：实体周边 = 买进再卖出 = **最字面意义上的"贸易"**，比数字产品更难辩解，且多出物流、售后两个可触达实名的接触面
- 🔴 **分辨率硬伤**：现有手机壁纸约 1179×2556px，**A3@300dpi 需 3508×4961px、A2 需 4961×7016px** → 上实体前必须重做高清源文件
- 🔴 带书号的画册属「图书」，需**出版物经营许可证 + 固定经营场所** → 出局
- ✅ 更该先做的替代：**卖「高清印刷级源文件」数字 SKU**（¥49–129，附自印授权）—— 零物流、零售后、零保证金

## 四、推荐组合（主 + 副 + 探路）

```
主线  方案 2（内容飞轮 + 名单）        ← 每周固定投入，这是唯一在修真问题的事
副线  方案 1（站内直卖拿第一笔）        ← 本周就上，3–7 天见钱，成本 0
探路  方案 3 的「只验证类目」一步       ← 花 2 小时 + 等审核，不开发
后置  方案 4（C 档数字品）              ← 名单 ≥300 后再谈
冻结  众筹 / App / 实体 / 一切境外平台
```

**理由**：方案 1 解决"有没有人愿意付钱"，方案 2 解决"有没有人来"，两者必须**同时**跑 ——
只跑 1 会得到"零订单"的假结论，只跑 2 会拖半年才验证付费意愿。方案 3 是**零成本期权**：花审核周期买一个"2026 年微信给个人开了虚拟支付"的信息差。

## 六、agent 团队怎么配最省 token（本次实测经验）

> **先说结论**：省 token 不靠"插件"，靠**分工**和**输出约束**。本次没找到已装的省 token 插件；
> 真正的杠杆在 workflow 的 **schema 约束** 和 **模型分层**。

### 本次实测数据
- 6 个 agent 并行调研 5 条路线 → **3 条成功、2 条返回 null、综合 agent 也返回 null**
- 失败的**全部原因**：**schema 嵌套过深**（综合 agent 的 `options` 是对象数组的数组）→ agent 直接放弃返回
- 成功的 3 条**输出过长**（约 15K token），信息密度只有一半

### 五条纪律（下次照做）

| # | 纪律 | 本次验证 |
|---|---|---|
| **1** | **schema 保持扁平** —— 最多两层，数组里只放字符串，不要"对象数组套对象数组" | ❌ 违反了，综合 agent 直接 null，白烧一次 |
| **2** | **共同前提只写一次**，用变量插值进每个 prompt | ✅ 做到了，5 条路线共享同一段 CTX |
| **3** | **在 prompt 里明令"输出紧凑、禁止长篇"** | ⚠️ 写了但仍偏长，下次加**字数上限** |
| **4** | **分层：agent 只做"外部信息检索 + 独立子任务"，判断自己做** | ✅ 判断类工作（综合排序）由我做，比 agent 更准且省一次全局重传 |
| **5** | **模型分层**：批量检索用便宜模型，判断用强模型（workflow 的 `agent()` 支持 `provider`/`model` 覆盖参数） | ⏳ 本次未用上（模型清单读不到），**下次优先试用这个** |

### 不该交给 agent 的活
读写本地文件、跑脚本、改配置、做最终决策 —— **我自己做更快更准**，agent 只适合"我这边查不到、且不需要我的上下文"的外部信息。

### 具体到第七境的常驻 agent 配置建议（若要做）
```
调研 agent   × 2–3   只做外部检索（平台费率/政策变化），每月跑一次
监测 agent   × 1     商标公告 + 平台规则变更，结构化输出
不要用 agent：写文案、做图、改站点 —— 这些有本地脚本或直接做更快
```
