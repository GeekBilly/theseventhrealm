## 二、⚠️ 但真正的问题是这三条（已实测确认）

### 🔴 缺口 1：登录入口敞开且无失败限制

```
实测（2026-10-04，从外网未登录）：
  /wp-login.php        → 200 · 9195 字节（登录页正常返回）
  /xmlrpc.php          → 405（端点在，只是方法不对）
  /wp-admin/           → 302（重定向到登录，正常）
  /?author=1           → 301 → https://theseventhrealm.com/author/admin/   🔴 用户名枚举成功
  /api/health          → 404 ✅（没有这个路由，好）

连续 3 次错误密码登录：
  第 1 次 → HTTP 200
  第 2 次 → HTTP 200
  第 3 次 → HTTP 200
  ⇒ 每次都正常处理，【没有任何失败次数限制或延迟】🔴
```

**⇒ 知道用户名（admin）+ 入口敞开 + 无限制 = 爆破的完美条件。这就是 1436 次的来源。**

### 🔴 缺口 2：用户列表通过 REST API 公开

```
GET /wp-json/wp/v2/users  →  200 · 1511 字节

返回：
  id=2  name=MollyBot_No.2  slug=mollybot_no-2   ← 我们的 AI 发布账号
  id=1  name=第七境          slug=admin            ← 管理员，slug 直白写着 admin
```

**⇒ 两条信息都暴露了**：
- 管理员的 slug 是 `admin`（配合 `/?author=1` 可确认）
- 存在一个机器人账号（**低风险，但没必要公开**）

**⇒ MollyBot_No.2 的来源已查清**（`07-课程/ch04-网站权限接入实录.md`）：
> 「建一个专用账号（本案例用户名 `MollyBot_No.2`），角色选编辑（Editor）」

⇒ **是我们自己的 AI 发布账号，不是入侵** ✅

### 🔴 缺口 3：没有安装任何安全插件

```
GET /wp-json/  →  命名空间 5 个，全部是 WP 核心：
  oembed/1.0 · wp/v2 · wp-site-health/v1 · wp-block-editor/v1 · wp-abilities/v1

⇒ 没有 wordfence / limit-login-attempts / wps-hide-login 之类
⇒ 与「缺口 1」实测的"无失败限制"互相印证
```

## 三、修复建议（按性价比排序）

| # | 措施 | 成本 | 效果 | 需要什么 |
|---|---|---|---|---|
| 1 | **Cloudflare WAF 规则拦 `/wp-login.php`**（只放行你的 IP） | 免费 | 🔴 立刻止住 1436 次 | 用户操作 CF 后台 |
| 2 | **Cloudflare Rate Limiting**：`/wp-login.php` 每分钟 ≤5 次 | 免费版可做 | 大幅降速 | 同上 |
| 3 | **关掉 `/?author=` 枚举**（子主题 `functions.php` 加 3 行） | 0 成本 | 消除用户名枚举 | 我可以改（走申请单） |
| 4 | **限制 `/wp-json/wp/v2/users`**（只返回有已发布文章的作者） | 0 成本 | 隐藏账号列表 | 同上 |
| 5 | **管理员改名**（不用 `admin`）、或至少改 slug | 低 | 消除最直接的攻击面 | 用户后台改 |
| 6 | **开启双因素认证** | 低 | 就算密码泄露也进不来 | 需装插件 |
| 7 | **限制登录失败次数**（装 limit-login-attempts-reloaded） | 低 | 直接掐死爆破 | 需装插件（用户操作） |

**⇒ 1 + 2 是当天就能见效的，而且不碰站点代码。**
