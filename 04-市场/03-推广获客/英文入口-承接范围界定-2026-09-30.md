# 英文入口 · 承接范围界定（2026-09-30）

> **一句话结论：现在做 L1「一页英文门面 + 双引擎索引」，不做表单、不做英文站、不碰海外社媒。**
> 成本约 1 小时，不新增任何合规暴露，且是未来所有出海动作（Gumroad / 众筹国际版 / 版权合作 / 小说出海）**绕不过去的前提设施**。
>
> ⚠️ 先分清两件事，混在一起会把这条线做歪：
> - **海外推广**（IG / Pinterest / Reddit 发帖）＝ **已暂停**，触 R-20（跨境信道）+ R-19。见 `海外线-访问合规评估-2026-09-30.md`
> - **英文入口承接**（站上放一个英文页）＝ **可以做**，全程本地发布 + 被动索引，人不需要登录任何境外平台

---

## 一、为什么"不做推广"却仍值得做英文入口

### 1.1 现状是真·零英文，等于把偶发流量全倒掉

| 项 | 现状 |
|---|---|
| 站上有英文内容吗 | **没有**。全站中文，包括导航、页脚、法务页 |
| 英文访客进来会看到什么 | 满屏中文，浏览器翻译质量对"书法/字形/朝代"这类话题基本失真 → **100% 跳出** |
| 英文访客从哪来 | Googlebot 已在抓（HTTP 200），但新站**没有任何英文页面可供排名** |

**关键判断**：即使不推广，Google / Bing 也会零星带英文访客来（搜 "Shang dynasty oracle bone script"、"Chinese character evolution poster" 这类词的人真实存在，而我们的内容恰好就是这些词对应的东西）。现在这些人来了只能掉头走，**而承接成本只有一页 HTML**。

### 1.2 它是"资产"不是"活动"

区分两类投入：

- **活动**：发帖、更新社媒、维护粉丝——需要持续投入、持续留痕、持续花时间。❌ 现在不做
- **资产**：一页静态英文门面——写完就躺在那儿，**零维护，条件具备时原地启用**。✅ 现在就该有

将来任何一个海外动作的前置条件都是"你先给我一个能看的英文网址"：Gumroad 上架要、众筹国际版要、版权方/译者/播客来询价要、小说出海要。**现在不做，将来每个项目启动时都要临时补**。

### 1.3 英文访客唯一能消费的内容 = 图（这一点决定了页面主推什么）

语言是墙，但**壁纸不是**。字形演变图、金句壁纸——英文访客不需要翻译就能看懂、就能用、就能喜欢。

所以英文页的**主推位不是"读我们的历史"（他们读不了），而是"拿走这些图"**。这是 L1 页面的设计基准，也是它和"中文站翻译版"的根本区别。

## 二、四档范围与取舍

| 档 | 内容 | 成本 | 判断 |
|---|---|---|---|
| **L0** | 现状：零英文 | 0 | 每天在浪费偶发流量 |
| **L1** | **单页 `/en/` 门面**：这是什么 / 能拿走什么（壁纸直链）/ 联系方式（mailto）/ 诚实告知其余为中文；页脚加 EN 入口；进 sitemap；加主动索引 | **≈1 小时** | ✅ **本次做** |
| **L2** | L1 + **邮件订阅表单** + 英文 privacy/terms + GDPR 口径 | 3–5 小时 + 依赖第三方 | ⏸ 等触发条件（见 §四） |
| **L3** | 真正的英文站：16 朝代英文版 + 英文藏品页 + 英文商城 | 数十小时 | ❌ 不做。0 流量的前提下是给自己盖空商场 |

### 2.1 为什么 L1 不收邮箱（这是你最关心的那问）

直觉是"收英文邮箱嘛，放个表单就完了"。但把账算清楚会发现**现在放表单是负收益**：

| 维度 | 表单（MailerLite） | mailto（L1 采用） |
|---|---|---|
| 收到邮箱的效果 | 好 | **几乎一样**——而且来信的是**高意愿真人**，打开率远高于表单灌进来的 |
| 合规负担 | 欧盟访客即触 GDPR：需数据处理者披露 + 目的说明 + 退订机制 | **零**。只是收信，跟现有隐私政策第四、六条口径完全一致 |
| 第三方依赖 | 需 MailerLite 嵌入码（**目前还没到**，国内线也在等）、免费版还要求 SPF+DKIM、涉"数字产品"要连 Stripe | **无依赖** |
| 英文法务页 | M13 英文 privacy/terms **已随海外线冻结**，没它就上表单＝裸奔 | 不需要 |
| 流量前提 | 英文流量 **≈ 0** → 表单 100% 空转 | 空转但零成本 |

**结论**：表单要的不是"放上去"，而是"有人往里面填"。第 5 行没成立之前，前四行的代价都是白付。

L1 的替代方案是一句话 + 一个邮箱链接：

> *Want the character series as it comes out? Write to me and I'll add you to the list.*

来信都是真人高意愿，手工加进同一份名单，**一个名单不分裂**。等 MailerLite 到位，把这份手工名单一次性导入即可。

## 三、L1 具体做什么（交付清单）

### 3.1 页面（`/en/`，slug = `en`）

| 区块 | 内容 | 说明 |
|---|---|---|
| Hero | ~~`THE SEVENTH REALM ™`~~ → **`TANTSE ™`**（2026-10-02 英文品牌**定为 `TANTSE`**；中文品牌仍为「第七境」）+ 一行定位 | 用站点同一套样式的英文对应版（宣纸白 + 衬线 + 朱砂点睛） |
| What this is | 3 句：独立创作者项目 / 用汉字字形演变与朝代长卷讲五千年 / 个人视角的整理，不是学术机构 | 口径与法务页"一个个人创作者"一致，**不虚构主体** |
| **Take something with you** | **主推位**：金句壁纸 32 张 + 字形线，**直链下载** | 图无语言障碍，是唯一能被真正消费的东西 |
| What's inside（中文区导览） | 5,000 Years / 16 dynasties / collection，每项**诚实标注 "in Chinese"** | 不装成英文站，反而体面；也是给将来 L3 留的索引位 |
| Contact | mailto + 订阅那一句 | 见 §2.1 |
| Footer note | "This site is primarily in Chinese. English coverage will grow." | 主动管理预期，减少跳出 |

### 3.2 技术动作（4 条，全部本地/零账号）

1. **页脚加 EN 入口**（一级导航不加，避免打乱中文站 7 项结构）
2. **进 sitemap**：新建页面自动进 `wp-sitemap.xml`（无需额外动作）
3. **Google 侧**：robots.txt 已声明 `Sitemap: wp-sitemap.xml` ✅（已核实线上生效）→ 被动发现已具备，**Google 侧无需再做任何事**
4. **Bing / Yandex 侧：启用 IndexNow**（见 §五，本次新打通）

### 3.3 明确不做（防止范围蔓延）

- ❌ 不翻译 16 朝代页、不做英文商城、不做英文藏品页
- ❌ 不放表单（理由见 §2.1）
- ❌ **不做 hreflang**：需改子主题 `functions.php` 注入 `<head>`。按 R-12「主题包上传是稀缺操作，只有子主题能办的事攒批再传」，**登记待办、攒批时一起做**（单页阶段 hreflang 收益本就极小）

## 四、L2 升级触发条件（写死，避免无限期挂着）

L1 上线后，**满足任一条**即启动 L2（上表单 + 写英文 privacy）：

| # | 触发条件 | 怎么观测 |
|---|---|---|
| A | 英文国家访客连续 2 周 **≥ 20/周** | **CF 站点看板已有国家维度**（M18 已接每日采集）→ 无需登录境外后台 |
| B | 收到 **≥ 3 封**英文来信（非本人测试） | `hello@` 邮箱 |
| C | MailerLite 嵌入码到位（国内线在等同一个东西） | 用户提供 |

> A 这条尤其关键：**我们有现成的观测手段，而且完全在合规范围内**——CF Web Analytics 的国家分布在本站看板里就能看到，不需要碰 GSC 或任何境外站长后台。所以"英文到底有没有人来"这件事，可以被客观回答，不用猜。

**L1 的验收标准不是英文邮箱数，而是**：`/en/` HTTP 200、进 sitemap、IndexNow 提交成功、页脚入口可点、CF 看板能看到 `/en/` 的访问。

## 五、本次新打通：IndexNow（零账号主动索引）

### 5.1 它解决了什么

Google 侧我们**不能主动提交**（GSC 需登录 google.com，触 R-20），只能等被动抓取。但 Bing 系有另一条路，而且刚实测确认可用：

```
POST https://api.indexnow.org/indexnow
{"host":"theseventhrealm.com","key":"<key>","keyLocation":"...","urlList":["..."]}
```

一次提交，**Bing / Yandex / Seznam / Naver 同时收到**（Bing 还给 DuckDuckGo 供索引）。Google 不参与 IndexNow，但 Google 侧本就有 robots.txt 通路。

### 5.2 实测证据（2026-09-30）

| 探测 | 结果 | 含义 |
|---|---|---|
| `GET https://api.indexnow.org/` | `301`，响应头带 `x-msedge-ref` | **真实微软边缘节点，境内可直连**，非运营商劫持 |
| `POST` 空体 | `400 InvalidRequestParameters / urlList field is required` | **接口真实在跑**，返回的是业务级校验错误 |
| `GET bing.com/ping?sitemap=...` | `410 Gone` | Bing 老式 sitemap ping **已废弃**，别再试这条路 |

### 5.3 合规判断（为什么它不触 R-20）

| 维度 | 情形 |
|---|---|
| 账号 | **不需要**。无注册、无登录、无后台 |
| 身份 | 不提交任何身份信息，API 侧只看到域名 |
| 内容 | 只提交 URL 列表，不含内容、不含数据 |
| 频次 | 发布时提交一次，非"高频长期留痕的经营性活动" |
| 性质 | 服务端之间的**技术性索引通知**，与"人在浏览器长期运营境外平台"不是一回事 |

**结论**：这是本次找到的**唯一一条合法的英文侧主动索引通道**，且比百度推送更"干净"（连 token 都是自己生成的）。

### 5.4 落地方式（沿用百度推送那套，不新增定时任务）

1. 生成 32 位 hex key → 上传 `https://theseventhrealm.com/<key>.txt`（内容＝key），走 cPanel 根目录，与百度验证文件同一路数
2. **待建**脚本：`11-运营/scripts/` 下新建一个名为 *indexnow-push* 的脚本，默认提交**全站 URL（含 `/en/`）**，去重文件 + 流水 CSV，结构照抄 `baidu-push.py`。**批准后再写**（key 文件未上线前写了也无法验证）<!-- deadlinks-ignore -->
3. **不新增定时任务**：并进每日晨检的索引推送步骤（与 7b 百度推送同一处，一次跑两条通道）
4. 新页面发布后顺手跑一次即可，不必天天推

## 六、本方案的三个已知缺口（诚实列出）

1. **无英文流量来源**：L1 是被动承接，不解决"怎么让人来"。真要有英文流量，仍需海外渠道——那是 R-20 的前置，条件不具备前不动。
2. **AI 搜索渠道未验证**：ChatGPT / Perplexity 等 AI 搜索是当下英文发现的重要入口，其爬虫（GPTBot / OAI-SearchBot / PerplexityBot）是否被 CF 放行**尚未核查**。CF 的 AI bot 策略此前只调整了 `Training` 分类（为解封 Baiduspider 时改的），Search/AI 分类状态待查。
3. **主体身份是硬限制**：我们只有"一个个人创作者"这个可披露口径，英文页上任何"团队/机构"式表述都不能写；`hello@theseventhrealm.com` 是唯一对外联络面。
