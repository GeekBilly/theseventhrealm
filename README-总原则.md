# P1 · 风险控制

## P1-1 ⚠️ R-19 是最上位前提（凌驾一切商业方案）

用户在**金融机构任职**，劳动合同禁止「以任何身份从事其他盈利性贸易、业务或职业」。

| 允许 | 禁止 |
|---|---|
| 内容创作、本地生产、站点维护 | **注册个体户 / 公司** |
| 品牌号运营（第七境） | **商标自助申请**（涉主体资格） |
| 著作权登记、在先使用证据 | 任何需要营业执照的平台入驻 |
| 年度汇算自行申报个税 | 让收入在单位侧可发现 |

**七条纪律（缺一不可）**：
1. 工作设备不留本项目文件
2. 不占工作时间与工作网络
3. 不向同事、客户透露
4. 不借公司渠道、不用公司邮箱
5. 保留时间线证据（证明是业余时间做的）
6. 账号一律用**「第七境」品牌号**，不用个人号
7. 留一条退路：**合规状态一旦变化，本前提自动失效**，需重新评估

> **R-19 无法靠"选收款通道"规避**——2026-10 调研已证实：几乎所有通道都要身份证实名 + 绑本人卡。
> 能做的是**压制暴露层级**：低金额（年 ≤10 万属免登记"零星小额"）+ 品牌号 + 不注册主体 + 不公开宣传经营身份。
> **这是"低风险"，不是"零风险"。任何人不得把它说成合规无虞。**

## P1-2 ⚠️ 跨境信道红线（不可试探）

**绝不为经营性活动使用非法定跨境信道。**

- 个人偶尔浏览 ≠ 经营性活动
- **高频、长期、留痕的跨境经营 = 单位处分 + 行政处罚**
- 所以：**所有境外平台（Gumroad / Paddle / Lemon Squeezy / Etsy / Ko-fi / Redbubble / 海外 App Store）默认排除**
- 处置永远是**换一条不需要绕过的路**，**不是找技术绕过**
- ⚠️ 遇到"这个平台很好但需要稳定跨境网络"→ **直接判否，不讨论**

## P1-3 ⚠️ 身份暴露最小化

**绝不出现**：真实姓名 / 手机号 / 家庭地址 / 单位名称 / 可反查的社交账号。

- whois 隐私必须长期开启；**截图一律打码**（只留域名/日期/状态这类非个人信息）
- 公开署名＝「一个个人创作者」+ 域名邮箱，**绝不虚构主体**
- 措辞不写"卖/收入/副业"；昵称头像不含真名或公司信息
- **动用户账号/身份类设置前，必须先说明属于哪条线、影响面多大**

## P1-4 ⚠️ 商标与品牌（R-01）

- **品牌名＝「第七境」（中文）/ `TANTSE`（英文）**；`theseventhrealm.com` 为主域
- 🔴 **「七境」在 9 / 41 类被北京漫游谷锁死**（`27072390` / `27083128`，至 **2028-10-13**）
  → 商标**注册大概率被驳**（代价已知情接受）；靠**共存 + 证据包**撑
- **盯续展**：2027-10-14 → 2029-04-13（月度公告监测，只查询不申请）
- 核准前用 ™，核准后用 ®；**未注册前不做实物周边售卖**
- ⚠️ **禁止重开「探赜」方案**（2026-10-02 已否决并归档，见 `99-归档/探赜-作废-20261002/README.md`）

## P1-5 ⚠️ 四类改动必须先出「执行申请单」

发布上线 ／ 删改线上内容 ／ 主题模版变更 ／ 涉安全合规金钱。

- 头部必写 `状态：待批 / 已执行 / 已验收 / 已否决`
- **执行完立刻回填**（写了单 ≠ 做了）
- 本地读写与草稿**直接做**，不用申请单

## P1-6 ⚠️ 收入与税务（2026 新事实，必须知情）

- **2025-10 起，平台按季向税务报送个人经营者信息**（税总 2025 年第 15 号公告，境内平台**无小额豁免**）
  → 项目原有假设「收入不公开可查」**已失效**。准确表述：**公众不可查，税务必然可见**
- 免工商登记的「零星小额」＝ **年交易额 10 万元**（《网络交易监督管理办法》§8）；**免登记 ≠ 免税**
- 🔴 **个人收款码用于经营收款违法**（《银发〔2021〕259 号》）→ **绝不贴个人码卖货**
- 个税走年度汇算自行申报；**不使用"经营收款"类聚合码，不隐匿收入**

## P1-7 合规红线（内容侧 / 版权）

1. 国内网络出版物需书号 → 数字品走海外（**已被 P1-2 排除**）、众筹走文创装帧册
2. **字体 OFL 1.1：不能单卖字体文件**
3. 古籍原文公有领域 → 值钱的是本版的**选 / 编 / 注 / 版式**
4. 🔴 **禁止使用「百家姓图腾」（王大有系）及一切衍生品** ——
   **已有生效判例**：2025 山西临汾中院，景区擅用其中 103 幅 → **判付 40 万元取永久授权**；
   另有 (2008)朝民初字第12476号、(2007)二中民终字第13723号。
   「图腾是全人类共同成果」的抗辩**未被采纳**。
   **整条线避开**：网络图包、姓氏图腾生成器、AI 仿制版、任何"参考其造型"的做法。
   （详见 `02-商品/06-姓氏线/姓氏视觉标识可行性-2026-10-02.md`）
5. 🔴 **博物馆/图书馆官网图片不得商用** —— 故宫数字文物库、国图、上博三家版权声明均要求书面许可，
   国图与上博**明确禁止商用**；台北故宫 OpenData、中研院各库**条款未核实且按地区限制**，同样禁用。
6. ⚠️ **上图开放数据仅授权非商业使用**（竞赛规则第 13 条）→ 付费商品须另行取得书面许可。
   **公版古籍可用，现代点校本/影印本/网络"大全"表不可用**（汇编与专有出版权）。
7. ✅ **版式规则与风格不受著作权保护** → 族谱版式（朱丝栏/版框/鱼尾）、饕餮云雷等**纹样母题**、
   仿汉印，**自绘即可安全使用**（但**绝不能抠扫描件**）。

# P2 · 成本控制

预算有三个维度：**token**（AI 用量）、**积分**（WorkBuddy 额度）、**时间与金钱**。三者都受约束。

## P2-1 ⭐ Token 成本控制（八条，2026-10-02 专项确立）

### 核心分工原则

> **agent 只适合做「外部信息检索」和「自包含子任务」。**
> **凡是需要我的全局上下文才能判断的活，自己干。**

理由：agent 不共享本会话上下文 → 要么重传一堆背景（费 token），要么它判断错（更费）。

| 交给 agent ✅ | 自己做 ✅ |
|---|---|
| 网络检索、平台政策核实 | 判断、取舍、排序、决策 |
| 独立成篇的自包含调研 | 读写本地文件、跑脚本、改配置 |
| 可结构化输出的信息收集 | 任何需要项目历史上下文的事 |

### 八条纪律

1. **schema 必须扁平** —— 最多两层，数组里只放字符串。
   ⚠️ **本次实测教训**：综合 agent 因 schema「对象数组套对象数组」**直接返回 null，白烧一次**。
2. **共同前提只写一次**，用变量插值进每个 prompt（不要复制粘贴到每一段）。
3. **prompt 里写死字数上限**（如"总计不超过 900 字"）—— 只写"紧凑"不管用。
4. **模型分层**：批量检索用便宜模型，判断用强模型（workflow 的 `agent()` 支持 `provider` / `model` 覆盖）。
5. **失败一次即降级，严禁重试循环。**
6. **大输出不整篇回读** —— 用 `grep` / 切片 / 只读需要的行。
7. **小样本先验证**：先跑 1 个 agent 看输出质量，再决定要不要铺开。
8. **能本地脚本做的绝不问模型**（算账、改文件、跑测试、生成图）。

### 本次调研的成本账（作为基线）
- 6 个 agent 并行 → 5 条路线，**只回来 3 条**（2 条 + 综合 agent 全因 schema 失败）
- 成功的 3 条输出约 15K token，**信息密度只有一半**
- ⇒ 下次：**扁平 schema + 字数上限 + 先跑 1 个试水**

## P2-2 常驻上下文预算（**随项目规模动态算，不是拍脑袋定的固定值**）

`MEMORY.md` **每次会话全量注入** → 它的长度就是**每轮的固定开销**。

```
预算 = 4000 + 200 × 活跃域数 + 100 × 规范文档数
区间 = [5000, 12000]；超上限必须靠「下沉 + 指针」消化，不许涨预算
```

**两个效率指标**（比总量更能说明问题）：
- **记忆密度** ＝ MEMORY ÷ 规范文档数 → 目标 **≤ 250**
- **记忆占比** ＝ MEMORY ÷ 全部 md 字符 → 目标 **≤ 0.60%**

⚠️ **超预算时的第一反应永远是"下沉细节"，不是"放宽预算"。**
但**系数必须按实测底线下标** —— 2026-10-02 的第一版系数（5200）定得过紧，
实测证明压到那个数只能动 P0，**等于用成本换风险，违反本文件的优先级**，故校准为上式。
完整规则与当前值见 `11-运营/记忆与归档规范.md` §五；脚本 `11-运营/scripts/memory-tidy.py --check`。

## P2-3 积分成本控制（已有硬约束）

月 1 日到账 **500 分**不结转；工作日 8 / 生产日 20 / 重活池 90（月 ≤2、单次 ≤45）/ 月末缓冲 54；**单日硬上限 60**。
⚠️ **禁用算术平均编预算**。脚本 `credits-budget.py`，规则 `11-运营/成本管控/积分预算与每日限额.md`。

## P2-4 时间成本控制

**每周 310–470 分钟** → **碎片做出口/维护，整块做生产**。

## P2-5 金钱成本控制

- **能本地模拟就不上线验证**
- 一次性支出必须论证；默认拒绝"先花钱看看"
- 现状：域名 ¥141/年（GoDaddy）+ $10.46/年（Cloudflare）

# P3 · 执行纪律

## P3-1 ⭐ 不虚构（最高诚信要求）

- **写不出原文，往往不是找不到，而是它本来就不在那儿** —— 引用溯源动笔前先确认
- 数据拿不准写「**未核实**」，**绝不编造数字**
- **区分「出处确证」与「文字已校」**，宁可写「未能确认」也不猜
- 来源必须可点回（URL / 文件名 / 行号）

## P3-2 ⭐ Agent team 使用规范（我作为 team lead 的职责）

1. **先判断性价比再拆** —— 拆分的收益必须大于重传上下文的成本
2. 拆分粒度：**每个 agent 一个自包含、可独立验收的问题**
3. 能用 2 个 agent 解决就不开 5 个
4. **失败即降级**，不重试
5. 结果**由我综合判断**，不外包决策
6. 每次用完记录：**几个 agent、成功几个、花在哪** → 沉淀进 P2-1

## P3-3 汇报规范

- 顺带发现的问题**先登记，别立即推用户操作**
- 布局/命名/措辞等非关键决策**直接定并汇报**
- 结论写在**回复正文**里，不要只说"见文档"
- 用户可能不看我给的文件 → 关键结论必须落在聊天里
