# 第 05 章 · 子主题装好了，页面为什么没变样？

> 这是建站路上最容易被吓到的一次「以为搞坏了」。真相是：**子主题完全正常，是我们的模版和页面类型对不上。** 本章讲透 WordPress 的模版层级，以及上线前怎么用一条命令看穿问题。

---

## 一、症状

子主题上传并启用成功，后台一切正常，但打开网站——**还是原来那副素净样子**，我们精心写的品牌横幅、吸附导航、水墨页脚一个都没出现。

第一反应通常是「主题没启用」或「插件冲突」。但实测出来的第一条证据就把这些可能性全排除了：

```bash
curl -s https://theseventhrealm.com/ | grep -oE 'class="[^"]*(home|blog|wp-theme|wp-child)[^"]*"'
```

返回：

```
class="home blog wp-embed-responsive wp-theme-twentytwentyfive wp-child-theme-seventhrealm-child"
```

逐字解读这个 class：

| 片段 | 含义 |
|---|---|
| `wp-child-theme-seventhrealm-child` | ✅ 子主题**确实已激活** |
| `wp-theme-twentytwentyfive` | 父主题在生效 |
| **`home blog`** | ⚠️ **关键**：当前是「首页 + 文章列表」类型 |

再查一条：我们的样式表加载了吗？

```bash
curl -s https://theseventhrealm.com/ | grep -o 'seventhrealm-child[^"]*' | sort -u
# → seventhrealm-child/assets/qijing.css?ver=1.0.0   ✅ 已加载
```

**样式表在加载，主题在生效，但模版没被用上。** 结论只有一个：**用来渲染这个页面的模版，不是我们写的那个。**

## 二、根因：模版层级与「页面类型」不匹配

我们在子主题里只放了一个 `page.html`。在 WordPress 的模版层级里，`page.html` 只服务于「**页面（page）**」这一种内容类型。而站点的首页被设成了「显示最新文章」，即**文章列表（home / blog）**——它去找的是 `home.html`，找不到就往父主题回落。

于是：

| 页面类型 | 用哪个模版 | 命中了吗 |
|---|---|---|
| 页面（如「道境」页） | `page.html` | ✅ 我们的 |
| **首页（文章列表）** | `home.html` → 父主题 | ❌ 拿到父主题的 |
| 单篇文章 | `single.html` → 父主题 | ❌ 拿到父主题的 |
| 404 / 搜索 | 父主题 | ❌ 拿到父主题的 |

**这解释了两个现象**：一是首页看不到我们的设计；二是外观看着「跟以前一样」——因为它确实还是父主题在渲染。

## 三、还有一个隐蔽问题：线上正文是旧版本

诊断时顺手把线上页面正文拉下来跟本地定稿做标记比对，发现问题比预想的深一层：

```bash
# 拉正文并查关键标记
curl -sS -u "$USER:$APP_PASS" \
  "https://站点/wp-json/wp/v2/pages/13?context=edit&_fields=content" \
  | grep -o 'logo-banner\|class="brand"\|<nav\|<footer' | sort | uniq -c
```

| 页面 | 长度 | 横幅 | 导航 | 页脚 | 判断 |
|---|---|---|---|---|---|
| 页面 13「第七境」 | 8870 | ❌ | ❌ | 1 | **旧版本**（加横幅、加导航之前） |
| 页面 32「5000years」 | 12863 | ✅ | ✅ | ✅ | 最新定稿版式 |

**教训**：线上内容和本地定稿会「各自漂移」。每轮改版都要用**标记比对**确认线上到底是哪一版，不要假设「我改的就已经上线了」。

## 四、修复路径（两步，顺序不能反）

1. **先改读取设置**（管理员操作）：设置 → 阅读 → 首页显示改为「一个静态页面」，选「第七境」页
2. **再换页面正文**（可用 API）：把两个页面的正文替换为「纯净正文版」（只剩 hero / 诗篇 / 时间线，**删掉页内自带的横幅、导航、页脚**——因为这三样已由模版统一输出）

> ⚠️ 顺序颠倒会出现新旧混排：模版输出的页脚 + 页面里残留的旧页脚 = 双页脚。

## 五、动手前必须做的事：备份 + 回滚预案

改任何线上正文之前，先做**只读备份**（拉取原始 JSON 存本地）：

```bash
mkdir -p 11-运营/backup
curl -sS -u "$USER:$APP_PASS" \
  "https://站点/wp-json/wp/v2/pages/13?context=edit&_fields=id,slug,content" \
  -o 11-运营/backup/page13-第七境-原始.json
```

**双保险回滚**：
1. WordPress 自带**修订版本**（页面编辑器右侧 → 一键还原）
2. 本地备份 JSON 里的 `content.raw` 原样贴回

## 六、本章速查表

| 现象 | 先查什么 | 命令/位置 |
|---|---|---|
| 换主题后没变化 | `<body>` class 里的页面类型 | `grep -oE 'class="[^"]*(home\|blog\|wp-child)[^"]*"'` |

## 附篇：子主题 v1.1 —— 「一次上传办四件事」（2026-09-28）

**背景**：决定暂缓数字周边上架（商标未注册），转回站点构建。子主题上传要用户手动点，次数很贵，所以把所有"只有子主题能办"的事攒成一批。

### 一、先判断"这件事编辑角色能不能办"

| 想做的事 | 后台常规入口 | 需要的权限 | 走子主题行不行 |
|---|---|---|---|
| 站点图标 favicon | 外观 → 自定义 → 站点图标 | 管理员 | ✅ `wp_head` 输出 `<link rel="icon">` |
| 标题 / description / OG 卡 | 装 Yoast / RankMath | 管理员 | ✅ `document_title` + `wp_head` 手写 |
| 导航、页脚 | 外观 → 菜单 | 管理员 | ✅ 子主题 `templates/page.html` |
| 全局样式 | 附加 CSS | 管理员 | ✅ `assets/qijing.css` |

**规则**：凡是需要 `manage_options` 的后台开关，一律可以用「子主题 PHP/CSS + 一次上传」绕过去——这是编辑角色能做的最大范围。

### 二、四条实战写法（可直接抄）

1. **图标**：先 REST 上传方图（`POST /wp-json/wp/v2/media`，带 `Content-Disposition: attachment; filename=…`）拿到附件 ID，再用 `wp_get_attachment_image_url(81,'full')`，附件被删也能回退硬编码 URL。
2. **标题**：用 `document_title` 过滤器整体接管，比改 `document_title_parts` 更可控；内页标题用 `get_queried_object()->post_title`，比 `single_post_title()` 稳。
3. **摘要**：`wp_strip_all_tags` **不会**去掉 `<script>` 里的文字，页面正文里带脚本时会把 JS 写进 description。必须先 `preg_replace('#<(script|style)[^>]*>.*?</\1>#si','',$raw)`。
4. **入口预埋**：把将来才启用的导航项写成 HTML 注释留在模板里，上线那天只取消注释，**省掉一整次主题上传**。

### 三、商标未注册期的合规姿势

- 未注册/申请中用 **™**，核准后用 **®**；反过来用是虚假标注，有法律风险。
- 页脚品牌行加 ™ 上标（`.tm{font-size:.5em;vertical-align:super;opacity:.55}`），实测 6.5px 不破坏版式。
- 法律行补一句「为商标申请中标识，未经许可不得用于商业用途」——既是声明，也是**在先使用**的证据痕迹。

### 四、成本

- AI 成本：约 6 次接口调用 + 1 次本地渲染验证，**0 积分**
- 人工成本：上传 zip，2 分钟
- 最大收益：把"站长该做的事"从等管理员权限变成自己能做的清单

## 附篇：用户说「没居中」时，怎么在不改内容的前提下修好（2026-09-29）

### 一、先量化，别争论「是不是错觉」

同一个页面里，用户反复说「文字不居中」，我量过一次说「全是 0 偏移」。**双方都没错，但测量方法有盲区**：我只量了区块容器，没往里量一层。

正确的量法（浏览器 console 里可跑）：

```js
// 对每个关键元素，取「文本实际墨迹范围」的中心，与「视口中心」比较
const w = window.innerWidth;
document.querySelectorAll('h2,.prose,.lone,.vpoem,.sanshi,.finale').forEach(e=>{
  const rng = document.createRange(); rng.selectNodeContents(e);
  const rs = [...rng.getClientRects()];
  const L = Math.min(...rs.map(r=>r.left)), R = Math.max(...rs.map(r=>r.right));
  console.log(e.className, Math.round((L+R)/2) - w/2);
});
```

- 用 **视口中心**做基准（不是父容器中心）——父容器本身可能就偏了
- **多量一层**：flex/grid 容器要连它**子项**的位置一起量，偏移常发生在内部
- 注意 `letter-spacing` 会让字符 rect 带上末尾间距，误差约 L/2，属正常

### 二、本案真凶：编辑器残留的空白 `<p>`

三列偏左 **50px**。原因是三个内容块之后有一个空白段落，它是 flex 的合法子项，白吃了 `gap:100px`。**偏移量 = gap ÷ 2**，这个数字关系是好用的指纹。

**修法的选择顺序**（越靠前越稳）：

| 方案 | 评价 |
|---|---|
| 改布局：`gap` → 相邻兄弟 `margin` | ✅ **首选**。跨浏览器、无跳动、不用改内容、以后编辑器再塞垃圾也免疫 |
| 服务端过滤正文空段落 | ✅ 副选，顺带清理垃圾，但只对服务端输出的内容有效 |
| CSS `:empty{display:none}` | ⚠️ Chrome 认「仅含空白」，Safari/Firefox 不认 → 不能单用 |
| JS 事后移除 | ⚠️ 会跳一下，且无 JS 时不生效 |

「**让垃圾骗不到间距**」比「**把垃圾删掉**」更可靠——这是本次最值钱的一句。

### 三、合规：没有法律主体时，署名怎么写

用户想用笔名，但**没有对应的登记主体**。正确姿势：

- **法律主体行**：写「**一个个人创作者**」＋域名邮箱，**不虚构任何主体名称**（虚构主体在收款、维权、发票环节都会出问题）
- **笔名**：放在「关于」页的**作者署名**处 —— 这是笔名的正当用法，也是对读者的诚信交代
- **私密信息**：真实姓名、手机号、通信地址**一律不上站**（域名 WHOIS 已开隐私保护；后台能看到 ≠ 可以公开）
- 等个体户/公司登记下来，再把主体行统一替换为登记名称

### 四、隐私政策：先写「一句话版本」

跨境个人站最容易把隐私政策写得又长又没重点。有效结构是**开头先给一段人话总结**：

> 本站没有账号、没有评论、没有表单、没有支付，因此拿不到你的姓名电话地址。
> 我们只知道：有人来过、看了哪几页、大概从哪个国家来 —— 而这是汇总的、匿名的、不用 Cookie 的。

后面再分节展开（安全日志 / 主动来信 / 匿名统计 / Cookie / 第三方 / 保留期 / 你的权利 / 跨境 / 未成年人 / 变更）。**诚实列清第三方**（CDN、主机、字体服务）比堆法条更有用。

### 五、统计：优先选「不需要同意横幅」的方案

`Cloudflare Web Analytics` —— 免费、**无 Cookie**、不采集个人身份信息、不做跨站跟踪 → **不需要 Cookie 同意横幅**，且站点已在 CF 代理下，面板选「自动安装」即可，**零代码改动**。

对比：Google Analytics 要同意横幅 + GDPR 合规成本 + 数据不在自己手里。**个人站在有交易之前，没必要背这个包袱**。

## 第六节 · 导航信息架构：为什么「二级菜单」是个人站最容易做错的地方

### 一、把「入口」和「承接页」分开想

同一个内容，两种挂法差别巨大：

| 挂法 | URL | 搜索引擎怎么看 | 代价 |
|---|---|---|---|
| 全塞一页 + 锚点 | `/5000years#shang` | 只收录**一个**页面，锚点不算新 URL | 零成本，5 分钟 |
| 每个朝代独立页 | `/5000years/shang/` | 16 个页面**各自可被收录** | 要写 16 页内容 |

**关键认知**：锚点只改变滚动位置，**不产生新 URL**，所以「商朝」「周朝」这类词**永远搜不到你**。如果你的商业模式要靠某个具体词带来流量（比如卖商周壁纸），那个词必须有自己的 URL —— 它就是商品的**承接页**（landing page）。

所以正确路线往往是**两步走**：先用锚点把导航跑起来（验证信息架构、零风险），等内容攒够了再把链接逐条换成独立页（URL 结构不变、页面正文不动）。

### 二、批量生成 N 个子页：内容与版式必须分离

手写 16 页会疯。正确分工：

```
数据文件（eras.py）    ← 只放文字：slug / 标题 / 年代 / 金句 / 正文 / 三卡
生成器（build.py）     ← 只放版式：套模板、拼 HTML
发布脚本（publish.sh） ← 只放动作：幂等 upsert + 体检 + 单发/全发
```

三个好处：**改错别字只动数据文件**（不碰版式）；**版式升级不用重写内容**；**发布可 `DRY_RUN=1` 先本地体检**。

### 三、导航的隐藏成本：子页会「不亮」

把二级菜单从锚点换成独立页 URL 之后，导航高亮**全部失效** —— 因为高亮脚本通常做的是**精确路径匹配**（`/5000years` === `/5000years`），而你现在访问的是 `/5000years/shang/`，一个都不等于。

修法是一条前缀归并：

```js
if (path.indexOf('/5000years') === 0) target = '/5000years';
```

**教训**：功能改完一定要用**真实 URL** 打开子页看导航高亮。本地 `file://` 预览测不出来（`history.replaceState` 被禁、pathname 不对），这类问题只在线上暴露。上线前先在本地跑一遍「假设 path 是 X，哪个导航项会亮」的逻辑模拟，比上线后返工便宜。

### 四、稀缺操作要攒批：子主题上传的排期学

只能靠人工上传 zip 才能生效的改动（子主题文件），必须**攒成一批**再传，而不是改一点传一次——每次上传都是一次用户等待 + 一次出错机会。

攒批的时候顺手做一件事：**把可以内联的东西内联**。比如新页面的专属样式（三卡网格、上下卷导航）直接写在页面 HTML 的 `<style>` 里，而不是进主题包。这样以后**调版式不需要再传一次包**，主题包只装「全局导航/页脚/图标」这类非它不可的东西。

### 五、验证链接别用正则扫 HTML

正则扫源码判断「有没有这个入口」，会踩两个坑：

1. **注释里预埋的链接会被抓到**（预埋是常见做法，将来上线取消注释即可）→ 误报成死链。
2. **HTML 实体/URL 编码**让匹配失真。

正确做法是**数 DOM 节点**：`document.querySelectorAll('.f-links a').length`，并且看 `offsetParent !== null` 才算**可见**。这个差别曾把「页脚 7 条活链」误判成「8 条、其中一条 404」。

### 六、验收清单（用完就能抄）

- [ ] 一级/二级项数正确，二级指向的 URL 全部 200
- [ ] 桌面 hover 两面板**互斥**（同时只开一个）
- [ ] `documentElement.scrollWidth === innerWidth`（无横向溢出）
- [ ] 手机 ≤640px：导航条高度、面板是否满宽、两组手风琴互斥
- [ ] **子页导航高亮**（用真实 URL 测，不是本地）
- [ ] 站内 sitemap 已收录新页（WP 自带 `/wp-sitemap.xml`，无需插件）
- [ ] 页脚法务页链接平铺可见（不能只藏在二级菜单里）
- [ ] 点链接测跳转时，先滚动到元素再点 —— 元素在视口外时坐标点击会**静默失败**

### 七、信息架构迭代：当二级菜单「太挤」，就把大类提上来

v1.5 时「上下五千年」下面挂了 4 个时期（共 16 朝代）的下拉，实测**一级栏虽然放得下，但鼠标一悬停就掉出一个 20 项的大面板**——用户第一反应是"有点拥挤"。

迭代到 v1.6 的做法：

1. **把一个"栏目"拆成"栏目 + 4 个平行大类"**。一级从 3 项变成 7 项：道境 / 上下五千年（保留为纯总览入口，承接品牌词）/ 传说与三代 / 秦汉魏晋 / 隋唐两宋 / 元明清·近代 / 关于我们。每个大类下拉只放 4 个朝代，面板变成**单列微型面板**（`.sub-list`），视觉重量瞬间降下来。
2. **保留原总览页作为品牌词入口**。不要因为拆了大类就把栏目页删掉——像「上下五千年」这种词是搜索流量入口，必须仍然一键可达、且在这一页高亮。
3. **移动端切简称**。7 个全称在 390px 下会撑成 3 行；给每个时期名写**双 span**（`.nf` 全称 / `.nsh` 简称，如「传说与三代 / 上古」），媒体查询里只显示一个，导航稳定在 **2 行 114px**。
4. **字体的统一是"信任感"的一部分**。一级用毛笔字、二级用宋体，看起来像两个网站；统一成同一款毛笔字后（一级 19px / 二级 16px）整条导航才像一件东西。注意毛笔字体字面更宽，**改字体要同时复测换行与溢出**。
5. **互斥是硬指标**。移动端手风琴最经典的 bug：给面板写 `display:grid` 时**选择器特异性与「默认隐藏」相同且靠后**，导致所有面板默认叠罗汉。正确写法是把显示规则**只写在选中态里**：`.ns-toggle:checked ~ .sub-list{display:grid}`。

### 八、上线后的复核脚本（一页搞定）

`11-运营/朝代页流水线/nav16-live-check.py` —— 对**线上真实域名**跑一遍：桌面/手机布局量值（行数、导航高度、横向溢出）、一级二级字体计算值、5 个 URL 的高亮落点、下拉互斥 display 状态、未启用入口的可见计数，并落 7 张截图归档。

两个写脚本时才发现的坑，值得写进课程：

- **`innerText` 对 `display:none` 元素返回空串**。下拉面板在桌面是隐藏的，用它读二级高亮文本只会得到 `null`/空 —— 必须用 `textContent`。第一轮复核就因此误判"二级高亮丢失"。
- **浏览器自动化脚本容易比命令行超时更长**。一次跑完桌面+手机+6 个 URL + 7 张截图会超过 2 分钟，要**放后台跑**（`run_in_background`），否则会被当成卡死而中断。
