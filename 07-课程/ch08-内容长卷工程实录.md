# ch08 · 内容长卷：上下五千年时间线的策划与量产（课程素材）

> 本章素材来自 `01-内容/` 的真实工作：一个人 + AI，把 16 个朝代从「每朝 400 字」做成「合计 8.2 万字」。
> 课程卖点不是"AI 能写文章"，而是**一个人如何给 AI 装上流水线与质检，把一次性的写作变成可验收的量产**。

## 一、目标（这一章要解决的问题）

- 现状：站点 16 个朝代页，每页约 430 字（只是导语 + 三段），撑不起 SEO，也撑不起"成书/众筹"这个商业目标。
- 目标：① 事件库 ≥100 个节点（短平快，立刻让时间线变厚）；② 每朝 4000–6000 字定稿；③ 合计 8–10 万字，够出一本书。
- 硬约束：**史实不能出错，争议不能回避，当代政治不能出现。**

## 二、操作步骤（可复现）

### 1. 先做"骨架"，再做"肉"

先做**事件库**而不是直接写长文：16 个 `<slug>.csv`，每行 `年份,事件,一句话,所属朝代`。

- 年份用**负数表示公元前**（`-1046` = 前 1046），一句话 ≤30 字（将来直接贴在滚轴上），字段内**禁用英文逗号**。
- 建 `build-all.py` 合并成 `all.csv` 并体检（4 列 / 年份可转整数 / 字数上限）。
- 结果：113 个节点。**这一步只用很短的时间，就让时间线页立刻变厚、长尾词立刻变多。**

> 课程里值得强调的取舍：**先做"结构化的小数据"，再做"非结构化的长文"。**小数据能被程序校验、能被复用到年表/滚轴/商品文案；长文只能一次性用。

### 2. 给每篇稿子定一个"模板"，而不是定一个"题目"

模板固定八段：金句+出处 → 导语（≤150 字）→ 6–11 节正文 → 字·物·事三卡 → 收尾 → 终句 → 引用出处 → 附：给 ops 的更新对照。

- 金句**沿用线上页已有锚点**（不改品牌调性），正文再展开。
- 最后那张「给 ops 的更新对照」表是关键：**内容稿写完的同时，把"线上页面怎么改"也写清楚**，交接零成本。

### 3. 把质检变成一条命令

`朝代稿/count.py`：统计每稿正文字数与目标差额 + 检查串语种字符（俄/越/日/希伯来）+ 正文拉丁词残留。

**每写完一稿必跑。**这是本轮最大的成本节省——AI 长文本生成会偶发"串语种"（一段中文里冒出俄语、越南语、假名）与自指残渣，肉眼极难发现，正则一查就出来。

## 三、踩坑与修复（本章最有价值的部分）

| 坑 | 现象 | 修复 |
|---|---|---|
| **串语种** | 正文里混入 `говорить` / `ách` / 假名 / 希伯来字符 | 写正则体检脚本，按字符区间扫描，每稿必跑 |
| **标题被吃掉** | 用 `s.replace(标题行, 新段落+标题行, 1)` 插入内容时，小标题被吞，出现孤立的「：xxx」残行，小节编号全乱 | 插入时**不要拿标题行当锚点**；收尾必须 `grep -n "^## "` 复核结构 |
| **锚点不唯一** | 同一句同时出现在正文和"三卡"里，`assert count==1` 失败 | 断言前先确认唯一性，必要时带上前置句 |
| **BOM** | CSV 首列解析成 `\ufeff年份`，`int()` 报错 | 全部用 `encoding="utf-8-sig"` 读文件 |
| **bash 变量吃中文** | `$VAR中文` 被当成一个变量名，`set -u` 报 unbound | 变量后紧跟中文一律写 `${VAR}` |

## 四、内容口径（可以直接当"AI 写作守则"讲）

1. **史实取通行说法**；有争议必须写明「有争议／一般认为」，并在文末"说明"段集中列出。
2. **不神化、不矮化**——"问天的是人，记事的也是人"。全书结尾落到「五千年，唯众生，无神迹」。
3. **引用必须有出处**，能引原文就引原文（金句 + 《书名 · 篇名》）。
4. **不出现当代政治**：最后一朝（觉醒年代）1912 年之后的部分，只记文字、出版、教育、信息技术层面的可查事实，不作政治评价。
5. **三卡（字 / 物 / 事）保留线上现有条目**，正文只做补充——改线上页时改动最小。

## 五、成果与成本

- **成果**：16 朝定稿，正文合计 **82,075 中文字**（目标 ≥80,000）。

- **可直接复用的资产**：`事件库/all.csv`（113 节点）、`count.py`（质检脚本）、各稿末尾的「给 ops 的更新对照」表。
- **成本**：全部在一轮对话内完成，主要消耗是长文生成的 token；**返工几乎全部来自"串语种"和"标题被吃"这两类可自动化拦截的错误** —— 这正是要写进课程的一句话：**AI 的错误不是随机的，是可预期的；把可预期的错误写成检查脚本，才是真正的效率来源。**
