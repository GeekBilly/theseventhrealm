> 触发：用户 10-17「把课程线也梳理一下，可以做付费课程引流——比如把 memory 压缩成索引模式节省 token，
> 非专业程序员、非 IT 行业的人用 WorkBuddy 一定不会有这种 sense，我帮他们省出来的 token 就是他们付给我的费用」。
> 本文档＝**现状盘点 + 方向评估 + 产品方案 + 引流路径 + 红线**。

## 一、现有课程线（A 线）盘点：素材很足，但从没卖过

**《一人公司建站实录：用 AI 把文化 IP 做成生意》**（07-课程/）

| 项 | 状态 |
|---|---|
| 章节 | 17 章（ch01–ch17），其中 8 章素材齐、9 章"待整理/规划中" |
| 体例 | 真人实录：目标 → 操作步骤 → 踩坑与修复 → **成本记录** → 可套用模板 |
| 对外销售 | **无**（月度记账 10-01：课程收入 ¥0，连续第 2 个月零收入） |

**判断**：A 线的问题不在内容，在于它卖的是"一个人的文化 IP 建站故事"——
满足的是**好奇与学习**，而这类需求被免费教程大量满足，替代品太多。
17 章没卖出去，不是产能问题，是**选品问题**。

> ⚠️ 这条结论很重要：**别再给 A 线加第 18 章了**。加章不会解决"没人买"，只会让沉没成本更大。

## 二、新方向（B 线）：AI 长项目的上下文管理

### 2.1 选题的硬货（本项目实测，不是道听途说）

| 实测项 | 数据 | 出处 |
|---|---|---|
| MEMORY.md 索引化 | **15,682 → 8,859 → 3,398 字符**（降 **78%**） | 成本-上下文 #5f |
| 单次请求注入构成 | 系统提示 ≈20K（**估算，省不掉**）｜记忆注入 6.3K｜压缩摘要 3.9K｜本轮 9.3K ⇒ 可变部分仅 19.6K | #5g |
| 成本公式 | **成本 = 轮次 × 当前高度**；自动压缩是**锯齿**不是线性（30MB → 6.3K 摘要） | #5g / #5d |
| 反直觉结论 | 清 `~/.workbuddy` 磁盘**救不了积分**（100MB+ 文件快照本就不进上下文） | #5d |
| 反直觉结论 | **会话历史不是信息源**："回想上次会话说过什么"正是成本失控的来源 | #5e |
| 反直觉结论 | 全树 `find`/Grep 会被 4G 目录**超时杀**（exit 137） | #5d |

🔴 **诚实标注**：上表中「系统提示 ≈20K」是**估算**；「记忆注入 6.3K」是**索引化之前**的实测。
索引化后每次请求省多少，属于**推算**（约 4K tok 量级），**未经二次实测**。
⇒ 对外表述一律用"**记忆注入降低 78%**"这个**实测值**，不要拿推算值当实测数据卖。**宁可少说，不可虚标。**

**结论很直白**：
1. 「AI 工具教程」这个品类**已被打到 10–19.9 元**，且用"每满 100 人涨价"的套路制造紧迫感；
2. 头部作者全是"5 年架构师""前产品经理""百万粉""大赛二等奖"——**讲资历，用户讲不过**；
3. 长尾惨烈：尾部专栏只有 **10–65 个订阅**。

⇒ **如果做成"又一份 AI 工具教程"，必死。** 10 元都未必有人买。

### 2.3 但差异化确实成立，靠这三条

| # | 差异点 | 为什么别人抄不走 |
|---|---|---|
| 1 | **有真实长项目 + 真实数字** | 别人讲的是"你要学会管理上下文"，你讲的是"我的 MEMORY 从 15,682 压到 3,398，实测降 78%"。**一个人 + AI 跑了 5 个月真实长项目，本身就是稀缺样本** |
| 2 | **卖的是"省下来的积分"，不是"学点东西"** | 教程满足好奇（可替代）；省钱满足 ROI（**可计算**）。付费动机性质不同 |
| 3 | **受众是"非程序员做长项目"** | 程序员遇到上下文问题会自己解决；非程序员遇不到（他们只做短任务）。**只有"非程序员 + 长项目"这个夹缝里的人是真痛点**——而用户正好站在这个位置 |

## 三、产品方案：**别做"课"，做"包"**

### 3.1 形态

| 不做 | 做 |
|---|---|
| 录播视频课（制作重、更新难） | **《长项目上下文管理包》**：可下载、可直接改、可直接用 |
| "教程"（10 元红海） | **工具 + 清单 + 实测数据** |

**产品内容**：

```
① MEMORY 索引模板（可直接套用的空模板 + 本项目 v22 实样对照）
② 上下文成本诊断脚本（测你的注入开销、定位最贵的那部分）
③ 上下文档位清单（哪些进上下文、哪些必须留在磁盘）
④ 实测数据表（本项目的真实数字，含"哪些方法无效"）
⑤ 落地 SOP（一页纸：新项目怎么从第一天就不长胖）
```

### 3.2 定价

**¥39（早鸟 ¥29）** —— 落在商品定价口径 **B 档 ¥12–129** 内。

定价理由（对外就这么说，是实话）：
- 配图占 79%、文字占 21%（43c）⇒ 文字类内容成本结构本来就轻，**不按"教程时长"定价，按"能省多少"定价**；
- 对照：重活日 411–973 分/天（43c）。**省下 20% 的积分消耗，一个月就赚回票价**；
- 🔴 **不要跟 10 元档对齐**——那一档卖的是"看的东西"，你卖的是"能直接用的东西"。对齐就是自杀。

### 3.3 平台

| 平台 | 费率 | 判断 |
|---|---|---|
| **小报童** | **约 5%**，微信登录 + 个人实名 | ✅ **首选**：文字专栏、付费习惯成熟、固定成本 0 |
| 面包多 | 已有 T-17 规划 | ✅ 数字商品自动发货，**与壁纸线共用同一收款通道** |
| 腾讯课堂个人版 | 0 年费，3–5% 佣金 | 备选 |
| 知识星球 | **20%**（10 万内） | ❌ 太高；且社群耗精力 |
| 小鹅通 / 千聊 | 年费 6800 / 3699 | ❌ 固定成本，绝不考虑 |

⇒ **结论：小报童为主 + 面包多为辅**（面包多正好是 T-17 要注册的通道，一鱼两吃）。

## 四、引流路径（先验证，再生产）

### 4.1 免费钩子：长文（不是广告）

#### 标题：先过证据关，再谈抓人

🔴 **口径铁律：标题里不许出现拿不出出处的数字**（见下表「对外」列）。

| 数字 | 值 | 出处 | 对外 |
|---|---|---|---|
| 体验版 | `isPaidUser: false` | `fetch-credits.sh` 实测 · 2026-10-17 21:15 | ✅ 可写 |
| 项目时长 | **22 天** | 站点首页面创建 **2026-09-26 06:50**（WP REST）+ 本地最早文件 09-26 | ✅ 可写 |
| 积分消耗 | **4,014.47**（cycleUsed） | 同上实测 | ✅ 可写 |
| 请求次数 | 近 7 天 **139** 次 | 同上实测（rowsInWindow） | ✅ 可写 |
| 单日峰值 | **633.52**（10-15） | 同上实测（byDay） | ✅ 可写 |
| 记忆压缩 | 15,682 → 8,859 → **3,398**（降 78%） | `成本-上下文.md` #5f | ✅ 可写 |
| 每日领取 | — | ⚠️ **无签到流水**；cycleTotal 存在 **+0** 的天（10-15→10-16 持平 4190） | ❌ **不许写「每日」** |
| ~~5 个月~~ | — | ❌ **无任何证据，系 10-17 草拟标题时虚标，已作废** | ❌ 禁用 |

**主标题（推荐）**

```
体验版 0 元，22 天烧掉 4,014 积分：我把记忆文件从 15,682 字压到 3,398 字
```

**备选 1**（保留原句式；「每日领取」降为「签到积分」）

```
我用体验版 + 签到积分撑了 22 天的长项目，把记忆文件从 15,682 字压到 3,398 字
```

**备选 2**（不写天数，改用体量证明「长」）

```
体验版 0 元做了个 16 朝 48 张成品的壁纸站：记忆文件 15,682 → 3,398 字的压缩实录
```

**备选 3**（三数字并列，适合知乎 / 腾讯云）

```
22 天、4,014 积分、139 次请求：一个体验版用户怎么把记忆文件压缩 78%
```

> **为什么主标题用「烧掉 4,014 积分」而不是「撑了 22 天」**：
> 「22 天」在 AI 长项目语境里说服力偏弱（读者会想「才三周」），
> 但「**22 天烧掉 4,014 积分**」证明的是**高强度**——冲击力更足，且全部实测可证。
> ⇒ **「长」不用天数撑，用消耗量撑。**

**结构**（可直接照此写）

```
① 症状：任务越做越贵，以为是文件太多（大部分人会先怀疑这个）
② 实测：先把数字摆出来——15,682 → 8,859 → 3,398，降 78%
   附体验版账本：22 天烧掉 4,014 积分、近 7 天 139 次请求、单日峰值 633
③ 三个反直觉（这是最值钱的部分）：
   · 清磁盘救不了积分（文件快照本就不进上下文）
   · 自动压缩是锯齿不是线性（别指望它一直涨，也别指望它救你）
   · 会话历史不是信息源（「回想上次会话」正是成本失控的来源）
④ 真杠杆：成本 = 轮次 × 当前高度 ⇒ 减少轮次，比清理文件有用
⑤ 方法：索引模式（宪法常驻 + 主题下沉 + 命中才读）
⑥ 钩子：上下文自检清单（免费，留邮箱即发）
```

## 五、红线

| 项 | 说明 |
|---|---|
| **R-19** | 个人实名（小报童需微信实名）无法规避，属"低风险"不是零风险。**压制暴露**：年 ≤10 万、不注册主体、不公开经营身份、署名「一个个人创作者」 |
| **10 万红线** | 连续 12 个月累计交易额 >10 万必须办照亮照（**多平台流水合并计算**——淘宝＋面包多＋小报童＋课程全算进去）⇒ 到线即停 |
| **不冒充官方** | 课程/文章里**不能有任何"WorkBuddy 官方合作/官方推荐"暗示**；身份就是普通用户 |
| **不泄露内部信息** | 讲**自己的实践经验**；不引用产品内部提示词、未公开接口、内部文档 |
| **不虚标数据** | 只用实测值（78% 那组）；推算值标注"推算"，不包装成实测 |
| **不承诺效果** | "省 20% 积分"这种话**不能写**——个体项目差异太大，写了就是虚假宣传 |
| **别在腾讯自家社区卖课** | 教用户少消耗 = 与平台商业利益反向，免费干货可以，挂付费链接风险高 |

## 六、执行顺序（**先验证，再生产**）

```
第 1 步（零成本）：写免费长文 → 发腾讯云开发者社区 + 站酷 + 知乎
第 2 步（看信号）：72 小时内看——有没有人问"怎么做到的"、评论区有没有同类抱怨
第 3 步（有信号才做）：做《上下文管理包》→ 上架小报童 + 面包多（¥39/早鸟 ¥29）
第 4 步：站内挂"留邮箱领自检清单"，接 Y1 邮箱 KPI
```

**判据**（照抄 `推广效果观测与下一步判据-2026-10-11.md` 的方法）：
- 长文发布满 3 天，**零问询 ⇒ 不做付费品**，说明需求是想象的；
- 有问询 / 有人私信问细节 ⇒ 立刻做，且**把问得最多的问题直接写进产品**。

**为什么必须先写长文**：A 线的教训就是"先生产 17 章，再发现没人买"。
这次反过来——**用一篇文章的成本，验证一个方向**。
