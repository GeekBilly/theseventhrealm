## 三、操作步骤（全部可复现）

### 0. 环境：在没有 brew 的 Mac 上搞到 ffmpeg

不用装 Homebrew，pip 一行搞定：

```bash
python3 -m venv ~/env
pip install imageio-ffmpeg numpy scipy
python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"
```

`imageio-ffmpeg` 会自带一个静态编译的 ffmpeg 二进制（macOS ARM 版），直接拿到可执行路径用，零污染。

### 1. 体检：先搞清楚到底坏在哪

不要凭耳朵猜，先跑数据。三个必测项：

```bash
# 响度三件套（这是能不能用的硬指标）
ffmpeg -i in.m4a -af loudnorm=I=-16:TP=-1.5:LRA=9:print_format=json -f null -

# 静音段（找要裁掉的空白）
ffmpeg -i in.m4a -af silencedetect=noise=-40dB:d=0.3 -f null -

# 波形取出来做频谱分析
ffmpeg -i in.m4a -f f32le -ac 1 -ar 48000 -   # stdout 就是 raw PCM
```

### 2. 诊断结果（这个案例的真实数据）

| 指标 | 数值 | 含义 |
|---|---|---|
| 集成响度 | −16.71 LUFS | 尚可，略偏低 |
| LRA 动态 | 10.80 | **偏大**，BGM 会忽大忽小 |
| 2–4kHz | −52.8 dB | **灾难**，清晰度没了 |
| 4–8kHz | −64.0 dB | **灾难**，空气感没了 |
| 有效带宽 | 8,229 Hz | 正常应到 16k+ |
| 主频 | 常年钉在 1420–1460Hz | 自相关 0.99–1.00，近乎纯音 |

**怎么判断"是不是被低通了"**：看高频相对电平。
正常录音 2–8kHz 应该有相当能量，掉到 −50dB 以下基本就是编码带宽被砍了（语音备忘录 / 低码率 AAC 常见）。
主频自相关接近 1.00 说明信号接近纯正弦，这是箫、埙、长笛这类乐器的特征——泛音本来就少，再被砍一刀就彻底闷了。

### 3. 修：核心是"把泛音造回来"

缺失的高频**无法靠 EQ 提回来**（那里根本没信号，提 EQ 只是放大噪声）。
真正有用的是**谐波激励**——用软饱和让波形产生新的谐波，再高通取出高频增量混回原信号：

```python
drive = 1.9
sat  = np.tanh(x * drive) / np.tanh(drive)   # 软饱和，产生奇次谐波
harm = sat - x                                # 只取"多出来的"谐波部分
harm = hp(harm, sr, 1000)                     # 高通两次，只留 1kHz 以上
x    = x + harm * 0.85                        # 混合
```

效果实测：2–4kHz +16dB，4–8kHz +27dB，8–14kHz +32dB，有效带宽 8.2k → 18.7kHz。

### 4. 其余链路

- **裁剪**：切掉尾部 −49dB 的静音（本例 127.2s 之后 2.8 秒空白）
- **EQ**：1.4kHz −5dB 削共振峰／260Hz +3.5dB 补厚度／3kHz 与 8kHz 高架 +7.5、+5dB
- **淡入淡出**：1.5s 进、3s 出（网页自动播放必备，不然一上来就"咚"）
- **压缩**：`acompressor=threshold=-20dB:ratio=3:attack=25:release=300`，LRA 10.8 → 6.0
- **响度**：`loudnorm=I=-16:TP=-1.5:LRA=9:linear=true`
- **限幅**：`alimiter=limit=0.97`

## 四、踩坑与修复

1. **临时路径会消失**：语音备忘录分享出来的文件在
   `~/Library/Containers/com.apple.VoiceMemos/Data/tmp/.com.apple.uikit.itemprovider.temporary.XXX/`，
   系统随时清。拿到第一件事是 `cp` 到工作区。
2. **`sysctl -n machdep.cpu.brand_string` 会误报**：本例报成 "Apple A18 Pro"（手机芯片），
   实际是 M5。要以 `uname -a` 的 `T8140` 加 `sw_vers` 为准，别拿错信息下结论。
3. **背景音乐的目标响度不是 −14**：−14 LUFS 是流媒体单曲标准。
   做网站 BGM 要压到 **−16 甚至 −18**，否则盖过页面内容，用户一进来就被吓到。
4. **别指望 EQ 救缺失的频段**：先做频谱确认那里有没有信号，没有就只能靠谐波重建。

## 七、进阶：把口哨旋律提取成谱、MIDI 和可听版本

素材其实是**口哨**吹的。这解释了一切：口哨近乎纯正弦，泛音极少，所以自相关相关度能到 0.99。

### 必须先纠正的一个坑：自相关的倍频误判

第一次分析时，自相关给出基频 560–723Hz。但频谱显示 500–750Hz 只有 −46dB（几乎没能量），
而 1250–1500Hz 才是峰值。**真实基频在 1400Hz 附近，723Hz 是自相关把周期算长了一倍的误判。**

教训：**测音高不能只信自相关**。对纯音乐器，FFT 峰值 + 抛物线插值更可靠；
判断依据是有没有那个频率的实际能量。自相关搜索范围设太窄（本例上限只到 800Hz）就会漏掉真基频。

### 算法链

1. **逐帧测基频**：4096 点 FFT（48kHz，分辨率约 12Hz）→ 限 400–3000Hz → 抛物线插值细化
2. **有效性判据**：峰值突出度（peak / 频谱中位数）+ RMS 双阈值，滤掉吹气噪声
3. **中值滤波**：5 点 medfilt 平滑音高轨迹
4. **音符切分**：连续 0.5 半音以内算同一个音，间隔 >0.12s 断开
5. **合并碎片**：<0.16s 且与前一音相差 <2 半音的并入前音（口哨滑音会切出大量碎片）
6. **量化**：减掉系统性音分偏差后四舍五入到 MIDI 整数音高

本例结果：135 → 129 个音符，音域 A5–A#6（13 半音），平均绝对音准偏差 24 音分，最大 49.5 音分。

### 怎么判断调性

看三件事：**结束音落在哪**（本例 A♯5 持续 4.8 秒，明确的主音收束）、
**哪些音出现最多**（F 与 A♯ 各 26 次，纯四度的主-属关系）、
**音阶能否套进去**（配上 D♯=4级、C=2级、D=3级 → **降 B 大调**成立）。

调内音占 89/129。剩下的调外音集中在 C♯／E／B／G♯，
基本是口哨音准游移的产物，不是真实的半音进行。

### 顺手合成一个可听版本

既然音符已量化到标准音高，就能反向合成。用加法合成模拟箫的音色：

```python
tone = sin(ph) + 0.16*sin(2ph) + 0.07*sin(3ph) + 0.03*sin(4ph)   # 基频+少量谐波
vib  = 1 + 0.004*sin(2π*5.1*t) * ramp(t, 0.25s)                   # 延迟起振的颤音
env  = ADSR(a=0.09, d=0.12, s=0.82, r=0.30)                       # 包络
```

再加一点起音处的气息噪声（衰减白噪 × 0.018），听感就接近真箫了。
这版比原始口哨录音更适合当品牌 BGM——音准是准的，音色也更贴「第七境」的水墨调性。

### 第二版：加滑音和呼吸，别让音符"按在那里起不来"

第一版的问题：音符起音后就是一条直线，缺乏生命力；音符之间完全断开。改法：

```python
# 1. 音高滑入：按音程大小决定滑音时长，指数插值
if gap < 0.30:
    glide = min(0.20, 0.055 + 0.020 * abs(12*log2(f0/prev_f)))
    fe[:ng] = prev_f * (f0/prev_f) ** (arange(ng)/ng)

# 2. 拱形呼吸包络（关键）：柔起 -> 微落 -> 渐强到顶 -> 缓收
arch   = 0.58 + 0.46*sin(pi*body**0.80)
amp    = min(0.24, 0.07 + dur*0.045)          # 长音起伏更深
breath = 1 + amp*sin(2*pi*0.58*t)

# 3. 音符尾巴重叠：TAIL=0.34s 自然衰减，下一个音接上来
```

| 指标 | 原箫音版 | 柔和版 |
|---|---|---|
| 音符间能量落差 | 106.8 dB（断开） | **2.7 dB（连绵）** |
| 音符内起伏 | 0.209（断音造成的假象） | 0.131（真实呼吸） |
| 起音时间 | 90 ms | 140 ms |
| 混响 | 无 | 2.2s 指数衰减，湿声 17% |

**踩坑**：柔版第一稿的音符内起伏反而只有 0.090，比原版还平——
混响湿声 30% 加上音符重叠把包络填平了。
把湿声降到 17%、压缩从 2:1 放到 1.5:1、呼吸幅度调大，才回到 0.131。
**教训：想要"连绵"和想要"有起伏"是两股相反的力，混响和重叠会吃掉动态，必须留出来。**
