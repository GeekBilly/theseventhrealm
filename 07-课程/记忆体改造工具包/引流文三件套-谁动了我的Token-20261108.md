### 正文

```
先说结论，再说过程。

【结论】
长项目里 AI 越用越钝、账单越用越贵，通常不是模型的问题，
而是「你的记忆文件被写胖了」，而每一轮对话都要把它重新发一遍。

【我的三个实测数字】
体验版 0 元，22 天：
· 记忆文件改造前：15,682 字符
· 改成索引模式后：3,398 字符（降 78%）
· 期间真实消耗：4,014 积分

【机制：成本 = 轮次 × 当前高度】
一次对话的账单 ≈ 你发了多少轮 × 此刻注入的内容有多高。
注意本地缓存和历史文件本来就不进上下文——
所以"清理磁盘救不了额度"这句话是真的，
真正在计费的是那份每次都被重发的记忆文件。

更反直觉的一点：上下文是递减资源，不是水桶。
内容越多，模型越抓不住重点。
扩大窗口不会解决问题，只会让你多读一遍无关的东西。

还有：自动压缩是锯齿，不是线性。
它确实会回落，但细节一起丢了，下一轮你还得重讲。

【我做的改造：索引模式】
上层只留"每次都用得上"的东西：
项目宪法、不可破的红线、一句话摘要的索引。
其余全部下沉成按主题拆分的文件，命中才打开。
操作步骤、日志、已完成的事，一概不进上层。

【工具化】
我把这套做法做成了两个脚本（体检 / 生成改造稿）和三个模板，
并且在 WorkBuddy 里封装成了技能，

我特意加了两条约束：
① 体检全程只读，绝不修改、删除、移动用户的任何原文件；
② 改造稿只新建文件，不动原文件；
③ 分类是启发式判断，输出是"建议"不是"判决"，最终由用户拍板。

【一个刻意的选择：不报"每月省 X 元"】
工具会算出你自己的数字（现在多少字符、改完多少、能降多少 token）。
但我不会替用户报一个具体的钱数——
除非他告诉我每天大概几轮对话、他用的模型每千 token 多少钱，
否则只给百分比和 token 绝对值。

理由很直接：省多少取决于他之后怎么用。
报一个漂亮的数字，对他没有好处，只会让这东西变得像又一个"AI 副业教程"。
```

## 三、掘金版（技术向）

### 标题

```
Agent 上下文治理：把 15,682 字的记忆文件压到 3,398 字，实测降 78%
```

### 正文

```
背景
长期使用 Agent 做项目，遇到了典型的「上下文通胀」：
对话越久越慢、账单越滚越大、而且 Agent 反复"失忆"。

实测（体验版 0 元，22 天）
· 记忆文件改造前：15,682 字符
· 改为索引模式后：3,398 字符（降 78%）
· 期间真实消耗：4,014 积分

核心机制
成本 ≈ 轮次 × 当前高度。
本地缓存与历史文件不进入上下文，"清磁盘"救不了额度；
真正每轮都在计费的，是那份每次都被重发的记忆文件。
且上下文是递减资源：内容越多，模型越抓不住重点。

实现
两个脚本 + 三个模板，打包成 WorkBuddy Skill（装上即用，无需配环境）：

1) memory_doctor.py —— 体检，只读
   · 主记忆文件 / 下沉文件自动发现
   · 按中文文本特征分节并分类：索引 / 原则 / 步骤 / 日志 / 归档
   · 输出三个数字、逐节处置表、孤儿文件、失效引用
   · 孤儿文件 = 主文件从未引用的下沉文件（纯浪费）
   · 失效引用 = 主文件提到但磁盘上已不存在

2) make_index_draft.py —— 生成改造稿，只新建文件
   · 输出「保留 / 下沉 / 归档」三段式
   · 每节给出建议文件名、存放位置、摘要填空位
   · 绝不修改原文件

设计约束（我认为比功能更重要）
① 工具不改用户的原文件，只读或只新建。
② 分类是启发式，输出标注为"建议"而非"判决"。
③ 不编造成本数字：没有用户自己的轮次与单价，就只给百分比与 token 绝对值。

踩过的坑（供参考）
· Python 模块名不能带连字符
· 章节正则要兼容 "##A 宪法" 这种无空格写法
· 引用检查要按相对路径在多个候选目录下探测，否则大量误报
· "标题含日期"不能直接判为日志（索引文件标题常带日期）
· Chrome headless 在受限环境下必须 --no-sandbox，否则无法初始化

工具包在淘宝店铺「第七境」，免费长文在站内。
```
