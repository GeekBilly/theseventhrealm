## 四、朝代入口的两种落地方式（关键决定）

| | 方案 A：锚点 | 方案 B：独立页 |
|---|---|---|
| 二级链接 | `/5000years#shang` | `/5000years/shang/` |
| 工作量 | 给每个 `.era` 加 16 个 id，一次改完 | 要建 16 个页面，且每页要有内容量 |
| SEO | 搜索引擎只认 1 个页面，「商朝」等词很难单独收录 | 每个朝代可单独被搜到，长尾词全归你 |
| 商业价值 | 低 | 高——将来「商·周」壁纸要靠朝代页做承接页 |
| 建议 | 立即先做 | 排到壁纸/内容产量跟上后逐批迁移 |

**推荐：先 A 后 B**。链接结构一次写成 `/5000years/shang/` 也行不通（页面不存在会 404），所以分两步：
1. v1.4：二级用锚点（`#shang` 等），导航立刻有二级菜单；
2. 之后每写一个朝代页，就把那一条链接从 `#shang` 换成 `/5000years/shang/`，其余不动。

锚点方案需要页面内容小改（给 16 个 `<div class="era">` 加 id）：
`sanhuang / xia / shang / zhou / qin / han / sanguo / jin / sui / tang / wudai / song / yuan / ming / qing / juexing`

## 五、技术实现要点（WordPress + 子主题限制）

1. **全部在子主题里做**：导航在 `templates/page.html`，样式在 `assets/qijing.css`。改这两处 = 用户重新上传一次 zip（编辑角色无主题权限）。
   → 这一批顺手把 v1.3 剩下的内容也可一起打包，**建议命名 v1.4**，避免频繁上传（约定第 9 条）。
2. **纯 CSS 下拉，不依赖 JS**：`nav li:hover` + `li:focus-within`（键盘/无鼠标也能开），`aria-haspopup` / `aria-expanded`。已有的 JS 只负责高亮当前页，保持不变。
3. **移动端（≤640px）**：下拉改成**手风琴**（点一级标题展开二级列表，同一时刻只开一个），不做 hover。16 项在手机上一次性铺开会很长。
4. **不做 hover 抖动**：面板与一级之间留 8px 的不可见"桥"，避免鼠标移向面板时菜单闪掉。
5. **页脚保持平铺**：关于 / 联络 / 隐私政策 仍在页脚列出（法务页可发现性 + 备案习惯），不跟着进下拉。
6. **当前页高亮**：现有脚本按 pathname 匹配，二级用锚点时会一起高亮父级，符合预期。
