## 一、新建文件 / 目录后的四件事

1. **登记**：新目录必须写进父级 README 或 `README-空间结构.md` 的目录树，否则下次体检会被当成「引用了但不存在」。
2. **跑路径体检**：`python3 11-运营/scripts/path-links-check.py`
3. **跑文本体检**：`python3 11-运营/scripts/lint-cjk-text.py <文件>`（见下节）
4. **命名**：脚本一律连字符 `<动词>-<对象>.py|sh`；文档命名规则见 `README-空间结构.md` 的「文件命名规范」节。

## 二、`lint-cjk-text.py` · 交付前必跑

```bash
python3 11-运营/scripts/lint-cjk-text.py <文件或目录>
python3 11-运营/scripts/lint-cjk-text.py --recent 20      # 最近改动的 20 个文件
python3 11-运营/scripts/lint-cjk-text.py <文件> --strict  # 加查「孤立拉丁词 + 英文短语」
```

**为什么必跑**：2026-09-30 同一批文件里**连续三次**混入肉眼极难发现的生成残渣（全角/半角混排、HTML 实体泄露、LaTeX 片段）。
这类字符一旦上线就**永久留在站点上**，事后几乎不可能被翻出来。

**默认只查三项高信噪比**：非中文语系字符 / HTML 实体残渣 / LaTeX 残渣。
`--strict` 才查「孤立拉丁词 + 英文短语混入」—— 技术文档里英文满天飞，默认开会让报告淹没在假警报里。

**自动跳过的范围**：`.sh` / `.py` / `.js` / `.css`、`<style>` 块、`href` / `src` 属性行、含 `<tag>` 或 `{` 的行。

**它只报位置，不自动改** —— 批量替换盲改会把正常的也改坏。逐条人工确认；确认是误报时**在该行写 `lint-ignore`** 豁免，
否则这行样例本身下次又会被判为残渣（`README-空间结构.md` 里的 `$WP_USER:$WP_APP_PASS`、`&lt;6 万` 两处即如此处理）。 <!-- lint-ignore -->

## 三、文档内互引：只写严格相对路径

**规则**：跨文件引用一律写**相对本文件**的完整路径，例如 `../04-史部别体/xx.md`。 <!-- deadlinks-ignore -->

**禁止两种写法**：

1. **「以某个子目录为基准」的裸路径**（`04-史部别体/xx.md`）—— 在任何标准解析下都不成立：既非相对本文件、也非相对工作根。 <!-- deadlinks-ignore -->
2. **跨目录的裸文件名**（`三国志.md`）—— 必须带目录。

**代价**：典籍库曾因此潜伏 **7 处死链**，全部指向从未存在过的文件名，肉眼读起来完全正常。

### `path-links-check.py` 的两处盲区（已补齐）

| 盲区 | 处置 |
|---|---|
| `.md` 里的相对引用抓不到 | 新增 `scan_md_refs()`，扫 `` `xx.md` `` 与 `[](xx.md)`，**按本文件**解析；跳过代码块 / 外链 / 锚点 / `<slug>` 占位 / 叙述性裸文件名 |
| 命名检查只到二级目录 | 延伸到**三级目录**；归档 / 备份目录豁免 |

- **它不扫 HTML 里的 `file:///` 素材引用** —— 大迁移后要另行补扫。
- **误报处置**：加**行级** `<!-- deadlinks-ignore -->`（`.sh` 用 `# deadlinks-ignore-file`）；
  **别整文件豁免**，整文件豁免会把真死链一起放走。
