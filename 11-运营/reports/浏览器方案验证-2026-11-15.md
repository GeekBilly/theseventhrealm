# 浏览器方案验证报告 · 2026-11-15

> 用户命题：「Chrome 插件已装好，以后不用无头浏览器策略了」→ 验证「现有方案里需要登录浏览器的部分能否弃用」，并在个人已登录 Chrome 里复验原方案。
> 本次为**只读验证**：未发布、未提交、未改线上、未停任何调度。

## 一、结论（先说答案）

**不能全部弃用。** 现有方案里其实混着三类浏览器，只有一类真正该弃用：

| 类别 | 实例 | 是否需登录 | 结论 |
|---|---|---|---|
| A. 本地无头渲染量测 | `measure-rhythm.py` / `dom-rect.py` / `rect-compare.py` / `measure-paradigm-align.py` | 否 | 与「登录浏览器」无关，本地成本 0，保留即可（不在弃用讨论范围） |
| B. 9222 无头积分浏览器 | `start-credits-browser.sh` / `fetch-credits-cdp.mjs` / `fetch-credits-shot.mjs` / `probe-usage-detail.mjs` | 是（已失效） | ✅ **可弃用/归档**：端口实测 `Connection refused`，晨检积分早已改走 `fetch-credits.sh`（cycleTotal 口径） |
| C. 9226 常驻有头 CDP | `start-xhs-browser.sh` + plist `com.theseventhrealm.xhs-browser`（04:50 补开，clone profile） | 是（有效） | 🔴 **不可弃用**：唯一承载小红书/抖音创作者中心登录态的实例 |

⚠️ 关键澄清：**9226 不是无头浏览器**，它是有头 Chrome + 调试端口 + clone profile（记忆库 `社交-小红书.md` 的既定路径）。「不用无头」不等于「不用 9226」。

## 二、扩展通道实测能力

`browser_id=2` = Google Chrome 扩展 `0.2.7`，profile `Default`，capabilities：`navigation / screenshot / cua / batch / dom_cua / user_tabs`。

- ✅ 具备：`user_open_tabs`（可列出个人 Chrome 的 63 个已开标签）、`tabs_new` / `tab_goto`、`dom_cua_get_visible_dom`（上限 20000 字符 / 200 元素）、`dom_cua_click` / `dom_cua_type` / `cua_*`、`tab_screenshot`。
- 🔴 **不具备**：任意 JS 执行（`Runtime.evaluate`）、CDP 端口、同源 `fetch()`、`DOM.getDocument depth=-1`、`Input.dispatch*` 精确坐标/触摸事件、后台无人值守调度。
- 实测不稳：`tabs_claim` 接管用户已有标签 4 次 → 3 次空返回、1 次 `provider invocation timed out`；`cua_scroll` 超时；CF 页 DOM 快照超时；`tabs_finalize` 先 `Browser command was cancelled`，后遇网络 502，本次补试返回 `MCP channel is not active` ⇒ 按「失败一次即降级」停止，**未反复重试**。

## 四、为什么 9226 不能弃用（三条硬理由）

1. **登录态不在个人 Chrome**：小红书、抖音创作者中心在个人 Chrome 均未登录。🔴 两个平台都是 **7 天窗口不可回溯、每天必采**（`xhs-stats.sh` / `dy-stats.sh`）。一旦停掉 9226 又没迁移登录态，连续 7 天取不到即**数据永久缺失**。
2. **脚本技术栈不兼容**：`xhs-stats.mjs` / `dy-stats.mjs` / `xhs-draft.mjs` / `fetch-credits-cdp.mjs` 全部依赖 `Runtime.evaluate` + 同源 `fetch()` 取数；`xhs-draft.mjs` 还用 `DOM.getDocument`、`Input.dispatchKeyEvent` / `dispatchMouseEvent` / `dispatchTouchEvent` 完成草稿填写、合集选择、原创声明与定时设置。扩展无 JS 执行能力，**无法平移**，尤其「定时没设上（STILL_OFF，连续 11 天）」这类问题只能靠 CDP 回读校验。
3. **晨检是无人值守**：05:00 由 launchd + `morning-collect.sh` 驱动；扩展通道只能由当前对话会话驱动，无常驻 CLI、无可被 plist 调用的取数入口。

## 五、扩展的合理定位（建议）

把扩展用作**人工只读复核与人工操作**，正好对上现有流程里「唯一人工项 ＝ 用户去草稿箱点提交」：

- ✅ 适合：积分页截图目检、MailerLite / 百度站长登录态目检、草稿箱人工点「发布笔记」、页面视觉核对。
- 🔴 不适合：每日定时取数、需要同源 `fetch` 的数据接口、需要精确坐标/触摸事件的复杂表单、无人值守任务。
- 🔧 若真要彻底弃用 CDP，属于**新工程**而非「弃用」：① 把创作者中心登录态导入个人 Chrome；② 用官方 API / 手动导出 / 扩展内容脚本 + 本地 HTTP 回传重写取数；③ 重新做 05:00 无人值守调度与 7 天窗口兜底。在此之前不建议动 9226。

## 六、风险与遗留清单

1. 🔴 **7 天窗口**：`xhs-stats.sh` / `dy-stats.sh` 每日必采，9226 掉线＝当天数据永久缺失；plist 04:50 补开须保留。
2. 🔴 **草稿提交**：草稿存在平台草稿箱，提交前须当场重勾「原创声明」与「内容含 AI 合成」，并手动选合集；定时是按篇设、发完即止。
3. 🔴 **CF 托管挑战**：WP 后台经扩展也过不去，远程探测结论不可信；线上状态判读仍以本地 curl（带浏览器 UA）为准。
4. ⚠️ **扩展限制**：`tabs_claim` 不稳定、DOM 快照 20000 字符 / 200 元素上限、无 JS 执行；`cua_*` 有超时记录。
5. ⚠️ **本次遗留**：`tabs_finalize` 未成功（MCP 通道断开），个人 Chrome 里留了本次验证开的标签（tab 64/65/66/67 及 CF 页），**建议手动关闭**；未改动任何调度、未删除任何脚本或记忆。
