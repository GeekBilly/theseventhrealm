## 二、体积构成（决定方案的关键）

| 类别 | 体积 | 文件数 | 适合进 Git |

| 文本/代码（md py sh json csv html css txt） | 48.3 MB | 2,246 | ✅ 完美 |

| **合计** | **5,084 MB** | **22,434** | |

### ⭐ 实测结果：`.gitignore` 落地后入库 **83.1 MB / 2,287 个文件**

分两步摸到的真实数字（预估 66MB 偏乐观，因为没算散落的图片）：

| 阶段 | 入库规模 | 问题 |
|---|---:|---|
| 只排大目录 | 404.8 MB | png 独占 350MB；且 `frames`/`frames_v` 两个英文帧目录**漏网** |
| 补精细规则后 | **83.1 MB** ✅ | 单文件最大 2.5MB，远低于 GitHub 100MB 红线 |

两个必须记住的坑：

1. 🔴 **三个帧缓存目录，不是一个** —— 中文的 `帧/` 5.9GB，英文的 `frames/` 159MB、`frames_v/` 67MB。
   只写 `**/帧/` 会漏掉后两个共 226MB。根治办法是**整个 `动画/` 目录排除**。
2. 🔴 **混合目录不能整个排除** —— `06-姓氏线/版式/` 里既有 115 个 png（25.6MB），
   也有 **145 个 html 模板 + 15 个 py 脚本**。整目录排除会把模板一起丢掉，正确做法是
   `目录/**/*.png`，只杀图片。

### 🔴 为什么不能「全量直接推」

全量里 **3.6 GB 是垃圾**：
- `02-商品/03-字形线/动画/帧/` — **2.8 GB**，静止帧重复截了约 50 遍（6,123 帧中 1,516 帧逐字节相同）
- `11-运营/.browser-profiles/` — **766 MB**，Chrome 缓存（真实内容仅 39MB）

Git 的历史**不可逆**：一旦推上去，删了的文件仍在 `.git` 里，每个 clone 都要拉一遍。**先分层，再初始化**——顺序反了就要重写历史。

## 五、方案：三层分工

### L1｜活资产 → Git + GitHub 私有仓库 ★ 主同步通道

**纳入**：`*.py *.sh *.md *.json *.csv *.html *.css *.txt *.yml`
**排除**（`.gitignore`）：
```
02-商品/03-字形线/动画/帧/
11-运营/.browser-profiles/
.workbuddy/
.work/
.scratch/
**/__pycache__/
**/*.pyc
**/*.old
.DS_Store
*.mp4
```

**✅ 实测入库 83.1 MB / 2,287 个文件**（见 §二）—— 首次 clone 几秒，日常 push 秒级。

`.gitignore` 已落地在项目根目录，共 101 行，按下面六类分层：

| 类别 | 规则要点 | 挡掉的体积 |
|---|---|---:|
| 系统垃圾 | `.DS_Store` `._*` | 微量 |
| Python 产物 | `__pycache__/` `*.pyc` `*.old` `*.bak` `*.log` | ~1 MB |
| 会话隐私 | `.workbuddy/` `.work/` `.scratch/` | 816 KB |
| Chrome 缓存 | `11-运营/.browser-profiles/` | **766 MB** |
| 渲染产物 | `动画/` **整个目录**（含 frames/frames_v/_p3/_p4） | **213 MB** |
| L2 冷资产 | 底纹/字体/成品/上架素材 + 混合目录下的 png | **≈822 MB** |

配套脚本 `qj-sync.sh` 内置**兜底拦截**：任何 >20MB 的文件试图进暂存区时自动中止并 `git reset`，
防止日后手工漏配规则导致大文件混进历史。

#### 🔴 补：`.workbuddy/` 被排除的代价与补救（2026-10-16）

上面「会话隐私」那条 `.workbuddy/` 排除的理由成立（里面有会话上下文和个人信息），
但它连带把 **`MEMORY.md`（每次会话开头自动注入的长期约定）和全部每日日志** 也挡在了 Git 之外
⇒ **它们既不在 GitHub 上，也不在 mini 的每日拉取里**。

这是整条备份线里最难重建的一环：项目文件丢了能 clone，**约定丢了只能靠回忆**。

补救方案：**每月一份脱敏快照进 Git**。

| 项 | 说明 |
|---|---|
| 脚本 | `11-运营/scripts/export-memory-snapshot.py` |
| 产物 | `11-运营/reports/MEMORY快照-YYYYMM.md`（同月覆盖，月末自动开新文件） |
| 内容 | 默认 `MEMORY.md` + `NOW.md`；`--full` 追加当月全部日志 |
| 脱敏 | privaterelay 邮箱 / `sk-` / `ghp_` / JWT / `password=…` 一律替换为占位符 |
| 幂等 | 内容未变**不写盘**，避免每天一次无意义 diff |
| 降级 | 任何异常只打印原因、exit 0，**不阻塞同步** |

已挂进 `qj-sync.sh` 的 `push` / `auto` 分支（在 `git add` 之前执行），
所以每日 02:30 的自动同步会把最新快照一起带走，mini 03:00 拉到。

⚠️ 两个限定：① 日志默认不入库，需手动 `--full`；② 快照是**脱敏版**，
真邮箱唯一来源永远是本地《11-运营/风险管控/账号与邮箱链路清单.md》，该文件不可删。

**两机纪律**（你的思路正确，但要工具化）：
```
改前：git pull --rebase
改后：git add -A && git commit -m "..." && git push
```
靠记性必忘 ⇒ 封装成一条 `qj-sync.sh`，两端各放一份。

### L2｜冷资产（不可替代二进制 ≈822MB）→ 不进 Git

Git 存二进制会把历史撑爆，且 diff 无效。三个选项：

| 方案 | 优点 | 代价 |
|---|---|---|
| **Time Machine + 外接硬盘**（推荐） | 唯一能救「误删」；自动每小时；还能救系统 | 需买硬盘（1–2TB 约 ¥400–600） |
| 云端副本（资料库／WP 媒体库） | 已有部分；异地 | 手动；不完整 |
| Git LFS | 与 Git 同流程 | 免费额度 1GB，822MB 贴边；超额付费；历史同样不可逆 |

**建议：Time Machine 为主，云端副本为辅。**

## 七、决策结果（10-11 用户确认）

| 项 | 决定 |
|---|---|
| **Mac mini 角色** | **纯备份机** —— 外接移动硬盘，每日定时从 GitHub 拉一次 |
| **GitHub 仓库** | 用户已有，地址待提供 |
| **冷资产（≈822MB）** | 用户自行决定是否备份到移动硬盘，**暂不动** |
| **写入端** | **MacBook 唯一** |

### 🔑 修正后的架构：单向流转，冲突从根上消失

```
MacBook（唯一写入端）
    │  qj-sync.sh：改前 pull --rebase，改后 commit + push
    ▼
GitHub 私有仓库（异地副本 · 中枢）
    │  backup-pull.sh：每日 03:00 pull --ff-only
    ▼
Mac mini 外接移动硬盘（本地第二介质）
```

**关键：链路上只有一个写入端。** Mac mini 从不 push ⇒ 不存在 merge 冲突，
`pull --ff-only` 永远不会因冲突失败（除非有人在 mini 上手动改工作区，脚本会自检并跳过）。

### 3-2-1 达成情况

| 原则 | 达成 |
|---|---|
| 3 份副本 | ✅ MacBook 工作副本 + GitHub + mini 外接硬盘 |
| 2 种介质 | ✅ MacBook SSD + 移动硬盘（另 + 云端） |
| 1 份异地 | ✅ GitHub |

### 三种灾难的恢复路径

| 场景 | 从哪恢复 | 丢失窗口 |
|---|---|---|
| MacBook 误删文件 | `git checkout` / GitHub | 0（若已 commit） |
| MacBook 整机损坏 | mini 硬盘 clone 回来，或重新 clone GitHub | ≤1 天 |
| GitHub 不可用 | mini 硬盘上有最近一次 pull 的完整副本 | ≤1 天 |

### 关于第 3 步：怎么处理那 10 处隐私邮箱

三个选项，我推荐 **B**：

| | 做法 | 优点 | 代价 |
|---|---|---|---|
| A | 原件入库，什么都不做 | 零成本 | 未来若误转公开即泄露 |
| **B** | **入库前替换为占位符，本地原件不动** | 内容保住了，隐私不外露 | 需要一次脱敏操作 |
| C | 这 3 个文件不入库 | 最省心 | 风控文档失去 Git 备份 |

> 泄露 relay 地址无法反查到真实身份。加上是**私有仓库**，真实风险不高。
> 但 B 的代价很小，做了更踏实。

## 九、配套脚本（均已语法校验 + 降级行为验证）

| 文件 | 用在哪端 | 作用 |
