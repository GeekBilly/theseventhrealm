## 一、结论速览

站**本身没坏**：DNS、证书、HTTPS、CF 全部正常，真实浏览器 UA 一律 HTTP 200。

真正的风险点是一个**渲染阻塞的第三方字体请求**：

```
https://fonts.loli.net/css2?family=Ma+Shan+Zheng&family=Noto+Serif+SC:wght@400;600&display=swap
```

它是 `<link rel="stylesheet" media="all">`，**浏览器必须等它下完才画第一屏**。
而它体积 325 KB，托管方自己又跑在 Cloudflare 上，实测**一次加载要跨 3 个域名、建 3 条 TLS 连接**，任何一环慢住，手机浏览器就表现为「打不开 / 一直转圈 / 白屏」。

> 附注：没开 HSTS 意味着第一次访问若用户输入 `http://` 或 `www`，会先有一次明文跳转，存在被劫持的机会窗。不是本次故障原因，但顺手建议开（CF 免费版就有，改动小）。

> ⚠️ 排障提示：本机常驻代理会毒化测试，`-4/-6` 与 `http://` 请求会被代理返回 403（`remote_ip=127.0.0.1`）。**测站点必须加 `--noproxy '*'` 并带浏览器 UA**，否则会把代理/CF 拦截误判成站点故障。

> 说明：本机出口在境外（CF Ray 落到 LAX / PDX），**上面的秒数不能代表中国大陆到 CF 的真实延迟**，
> 但「跨 3 个域名 / 3 次 TLS / 325 KB 阻塞」这个结构性问题是与地理位置无关的，任何弱网都会放大它。

## 三、三个候选根因，按可能性排序

### 3.1 🔴 首选：第三方字体阻塞首屏（可能性高）

加载链：

```
① theseventhrealm.com        (CF)  → HTML
② fonts.loli.net             (CF)  → 325KB CSS   ← 阻塞渲染，等它才能画第一屏
③ gstatic.loli.net           (CF)  → woff2 分片   ← 又一个新域名、又一次 DNS + TLS
```

- `functions.php` 第 22 行把它 enqueue 成 `media='all'` 的阻塞样式。
- 第 ②、③ 步都要**新解析 DNS、新做 TLS 握手**，且托管方是国内著名的免费公益镜像站，稳定性由它自己决定，我们无法控。
- **为什么偏偏是「安卓自带浏览器」打不开**：
  夸克 / UC / QQ 浏览器自带**云加速与 DNS 缓存**，能把第 ②③ 步绕掉或快速失败；
  系统自带浏览器（Chrome for Android、华为浏览器等）**直连 + 严格执行渲染阻塞**，
  一旦第 ② 步超时，就直接判定「网页无法打开」，而不是「先给你看没字的版式」。

### 3.2 🟡 次选：老安卓不认 Let's Encrypt 的新证书链

- 链末端是 `ISRG Root X1`，**Android 7.1.1 以下的系统根证书库里没有它**；
- 更早的设备唯一认的 `DST Root CA X3` 已于 2021-09-30 过期，LE 不再附送交叉签名；
- 若用户的手机是 Android 7.0 / 6.0 / 5.x，会直接报 **NET::ERR_CERT_AUTHORITY_INVALID**。
- 这条**只对老设备成立**。若他那台是 Android 10 以上，此条排除。

### 3.3 🟢 第三：中国大陆到 Cloudflare Anycast 的连通性

- CF 的部分 IP 段在国内被 QoS / 丢包，这是众所周知的问题；
- 但这条应该让**所有**浏览器都慢，不该只挑安卓自带浏览器；
- 只有在「他手机上别的浏览器也慢」时才成立。

## 五、修复方案（三选一，请你拍板）

### 方案 A — 字体自托管 + 子集化（推荐，最彻底）

- 把 Ma Shan Zheng（SIL OFL 1.1）与 Noto Serif SC（SIL OFL 1.1）下载到本地
- 用 `pyftsubset`（本机 fonttools 4.66 + brotli **已就绪**）按实际用字裁切，转 woff2：
  - Ma Shan Zheng：只留站点标题实际用到的那几十个字 → 预计 **10–30 KB**
  - Noto Serif SC：留 GB2312 一级字（3755 字）→ 预计 **600 KB–1 MB**
- 放到 `wp-content/upload/fonts/`，改 `functions.php` 输出本地 `@font-face`（`font-display: swap`），删掉 loli.net 引用
- 效果：**第三方域名归零**，同源复用已建立的 HTTP/2 连接，被 CF 边缘缓存（国内 ~20–50ms）
- 成本：一次性约 1 小时；后续每次加载从「325KB + 3 次握手」降到「首个请求就是自己的 CDN 缓存」

### 方案 B — 混合：标题自托管 + 正文用系统字体栈（体积最小）

- Ma Shan Zheng 子集自托管（保住书法标题的品牌观感）
- Noto Serif SC 改为系统衬线栈：`Songti SC, STSong, Source Han Serif SC, Noto Serif CJK SC, serif`
- 效果：全站字体请求总量降到几十 KB，**彻底断掉外部依赖**
- 代价：正文宋体在安卓上因 ROM 而异，观感不如 Font A 统一

### 方案 C — 止血：仅改成异步加载（10 分钟上线，不彻底）

- `functions.php` 里把字体 link 改成非阻塞（`media="print" onload="this.media='all'"`）
- 效果：字体再慢也不阻塞首屏，页面立刻可见，字体后到再换上
- 代价：首屏字体会有一次闪跳；根源（慢的第三方）还在

**我的建议**：先上 **C 止血**（今天就能做完），同时做 **A 彻底修**（批准后我来做）。
若你的目标是「让移动端别再挂」，只做 A 也行；若想今天立刻不白屏，C + A 串行最稳。

## 八、真因：Cloudflare 托管挑战卡死（08:20 追加）

### 8.1 判定依据

| 证据 | 说明 |
|---|---|
| 截图文字「正在验证您的请求，请稍候...」 | Cloudflare Managed Challenge 的中文文案，不是我们的页面 |
| 地址栏 state =「请稍候...」 | 页面 `<title>` 就是 CF 挑战页的，我们的站 title 是「第七境 · 五千年文明的水墨叙事」 |
| `security_level` = **medium** | 对「威胁分偏高」的 IP 会发起挑战 |
| `browser_check` = **on** | 浏览器完整性检查：header 不像标准浏览器就挑战 |
| `challenge_ttl` = 1800 | 挑战通过后 30 分钟内免验 |
| WAF 自定义规则 5 条 | 01 放行搜索引擎、02 挑战 `/wp-login.php` 等、03 拦 `curl/` `python-requests` UA、04 拦非白名单 `.php`、05 拦探测路径 |
| Managed Free Ruleset / Rate Limiting | **均为 0 条**，排除 |
| 我用老安卓 UA 从境外请求（完整 / 残缺 header） | **全部 200**，未被挑战 |

**关键推论**：挑战不是由 User-Agent 硬规则触发的（否则我这边也会被挑），
而是 CF 依据 **IP 威胁分 + 浏览器完整性** 做的**动态挑战**。
你手机的移动网络出口 IP（国内 CGNAT 共享出口）威胁分偏高 → 被要求验证；
而验证脚本依赖较新的 JS 能力，你的浏览器跑不动 → **永远停在验证页**。

### 8.2 为什么偏偏是「安卓自带浏览器」

- **能过的**：Chrome（新内核，JS 完整）；夸克 / UC（有云加速，实际是它的服务器去取，根本没走你手机的 CF 挑战判定）
- **过不去的**：系统自带浏览器 = 厂商定制的老 WebView。CF 挑战页要跑 `fetch` / `Promise` / `WebCrypto`，
  老内核在这里抛错，于是进度条永远转，用户看到的就是「打不开」。
- 补充：老旧设备还有一个叠加风险 —— 证书链末端是 `ISRG Root X1`，Android 7.1.1 以下不认识，
  会直接报证书错误（但你的截图是**验证页**，说明证书这关过了，可排除）。

### 8.3 修法（按优先级）

**① 关掉 Browser Integrity Check（最可能一步到位）**

```
PATCH /zones/{zone}/settings/browser_check  →  {"value":"off"}
```

- 影响：不再对「header 不全的浏览器」发起挑战。对内容站而言误伤成本远大于拦截收益。
- 可逆：随时一句 API 开回来。
- **风险**：会放进一些粗糙脚本的 GET 请求 —— 但你的 WAF 03/04/05 三条 block 规则仍在，实际风险很小。

**② Security Level：medium → low（跟随①一起做）**

```
PATCH /zones/{zone}/settings/security_level  →  {"value":"low"}
```

- 减少对「IP 威胁分偏高」的正常访客发起挑战。国内移动网络共享出口特别容易被误判。

**③ 兜底：给 HTML 导航请求加一条 Skip 规则（若①②还不够）**

```
(http.request.method eq "GET" and not http.request.uri.path contains "/wp-")
→ Skip: All remaining custom rules + Browser Integrity Check
```

- 只放行页面浏览，后台与 wp- 路径仍受保护。

**④ 你自己手机上的临时自救（不用改站）**

- 设置 → 应用 → 该浏览器 → 存储 → **清除数据/缓存**（清掉卡死的 `cf_clearance` 状态）
- 或直接用 Chrome / 夸克打开验证一次
