## 一、问题不是「某一处大」，是三套值并存

全站检索结果（`11-运营/scripts/audit-spacing.py`，43 页逐页解析内联 `<style>`）：

| 页面组 | 页数 | section 单侧 padding | 相邻两节实际空白 |
|---|---|---|---|
| 朝代页 94–109 | 16 | `clamp(44px,6vw,60px)` = 60 | **120px** |
| 总览 32 | 1 | `80px` | **160px** |
| 其余（首页 13 / 关于与法务 86–90 / 藏品 134 / FAQ 189 / 英文 193 / 藏品子页 344–360） | 26 | 未覆盖 → 主题 `qijing.css` 的 68 | **136px** |

**还有三处叠加，只看 CSS 值会低估：**

1. **padding 会相邻叠加** —— 两节各 60/68/80，中间就是 120/136/160，不是 60。
2. **Twenty Twenty-Five 主题给相邻块留 `margin-block-start:1.2rem`（=19px）**，
   `qijing.css` 里那条 `.wp-site-blocks > *` 清不掉它（section 在孙级，不匹配）。
   实测朝代页相邻节 = 60+19+60 = **139px**。
3. **金句行框比字高得多** —— `.final-line` 42px 字继承 `line-height:1.95`，
   行框 **82px**，视觉上字上下各多出 20px 空白。

截图那处（金句节）的实际构成：
`上一节 padB 60 + 节间 margin 19 + 本节 padT 60 + .finale padding 16 + .final-line margin-top 22 + 行框上留白 20`
= **197px** 空白，对一行 42px 的字。

## 二、做法

真源 `11-运营/spacing-rhythm.css`，注入 `11-运营/scripts/apply-rhythm.py`。

### 数值（桌面 1440 / 手机 390）

| 项 | 改前 | 改后 |
|---|---|---|
| 相邻两节 | 120 / 136 / 160（实测 139） | **84px**（单侧 42） |
| 手机相邻两节 | 120 | **60px**（单侧 30） |
| 段落之间 | 14px（margin 折叠后的实际值） | **20px** / 16px |
| 章标题之上 | 52px | 50px / 38px |
| 金句行框 | 82px | **63px**（line-height 1.5，字仍 42px） |
| 页脚上缘 | 70px | 56px |

### 关键四条规则

```css
section{margin-block:0!important;padding:var(--sp-sec) 24px}  /* 清掉主题那 19px */
.verse{padding:var(--sp-sec) 24px}          /* 金句节不再比常规节厚 */
.finale{padding:0}.final-line{margin-top:0;line-height:1.5}
.prose p{margin:var(--sp-para) 0}
```

### 为什么靠「页面注入」而不是改主题

`qijing.css` 在主题目录，本机只有 WP 应用密码、**没有 cPanel/FTP 凭据**，主题文件改不动。
所以 43 页各在正文末尾注入同一段 `<style id="qj-rhythm">`（528 字节，压成单行）。

**两条硬约束（都是踩过的坑）：**
1. 注入内容必须**无空行** —— `wpautop` 会往 `<style>` 里插 `<p>`，CSS 被整段吞掉（首页动画全白那次就是它）。
2. 注入位置必须在正文**末尾** —— 页面自己的内联 `<style>` 在正文开头，同特异性下后出现的赢。

**主题 `qijing.css` 本次未动**（无法部署）。将来若能上传主题：把 `spacing-rhythm.css` 合进去、bump enqueue 的 `ver`，然后删掉各页注入块即可，两者数值相同。
