# 安全 · PHP 与 WordPress（2026-10-27 建立）

## PHP2Shell：CVE-2026-109618 / CVE-2026-109619（CVSS 4.0 = 9.2 critical）

- **性质**：**PHP 解释器**的远程代码执行，**不是 WordPress 的漏洞**。
  🔴 **仅更新 WP／插件／主题修不了**，只能升 PHP 本身（北大通告原文：仅更新网站插件、主题或框架不能修复本次漏洞）。
- **触发**：特制 `multipart/form-data` 请求，**无需登录**。109618＝OOM 内存破坏；109619＝请求间失效状态残留。
- **在野**：PoC 已公开，watchTowr 确认利用尝试；CF 在补丁发布前已部署防护规则。尚无公开确认的攻陷案例。
- **修复版**：PHP **8.5.12 / 8.4.27 / 8.3.36 / 8.2.35**（按分支）；**8.1 及以下 EOL，无补丁，必须跨版本升**。
- **在本站**：PHP 由 **GoDaddy cPanel**（Select PHP Version / MultiPHP Manager）控制 ⇒ 升版本只能用户登录 cPanel 做，我无权限。
  升级后必须**重启 PHP-FPM/Web 服务**并复核实际生效版本（CLI 与 Web 可能不是同一个 PHP）。

### 缓解（不能替代补丁，按优先级）
1. `session.upload_progress.enabled = 0` —— **必须在 php.ini/FPM 池/服务器层**，用 `ini_set()` 或 `.user.ini` 无效（太晚），**改完重启所有 worker**。
2. `memory_limit = -1`，建议用 FPM `php_admin_value` 防被应用层改回；**不能根治**。
3. 收紧 `post_max_size`（无上传 8M / 有上传 32M），且 `upload_max_filesize < post_max_size`；代理层限制请求体大小与 multipart 分段数。
4. FPM `pm.max_requests = 1` 或 Apache `MaxRequestsPerChild = 1`（挡跨请求状态，掉性能）。
5. PHP 8.5 专属 `fatal_error_backtraces = 0`。
6. ⚠️ **不要用** `RLIMIT_AS` / `RLIMIT_DATA` 代替内存限制（反而触发漏洞路径）。⚠️ WAF 单独用不充分。

## 同期 WordPress 插件漏洞（仅当装了才相关）
- 6 个 CVSS 9.8 未授权漏洞（2026-10-16）：My Calendar / Mang Board / MailOptin / ELEX HelpDesk / Theme My Login / Sunshine Photo Cart。NVD 只给版本上界，**未给修复版**，需查插件页。
- 在野后门战役（CVE-2026-93836 WPC Product Bundles / CVE-2026-94504 Ninja Forms）：借存储型 XSS 用管理员会话装恶意插件（伪装 slug `wp-smart-thumbnails`），
  造**后台看不见的管理员**＋`?_wplogin=` 免密登录＋文件管理器，用 **mu-plugin** 持久化。
  🔴 **升级或删插件都清不掉后门**；文件时间戳被回写成旧时间戳 ⇒ **按修改时间排查会漏**。

## 本站远程检测的方法论（重要，避免重复踩坑）
- 🔴 **CF 托管挑战会把一切敏感路径探测统一返回 403**：`/wp-admin/`、`/wp-login.php`、`/xmlrpc.php`、`wp-config*`、`/.git/HEAD`、`/wp-content/plugins/*` 全是 403，
  连**随手编的不存在 slug 也 403**（2026-10-27 对照实验证实）⇒ **403 既不能证明存在，也不能证明不存在**，远程枚举插件/敏感文件这条路在本站无效，必须进后台或 cPanel。
- 远程**取不到 PHP 版本**（`functions.php` 4.4 段已移除响应头版本信息）⇒ 只能靠 cPanel。
- 已确认的良好项：WP 7.1.3 与官方最新一致；`/wp-json/wp/v2/users` 404 无用户枚举；`/?author=1` 301 回首页不泄露用户名；REST 110 条路由全为核心 `/wp/v2`，无插件端点。
