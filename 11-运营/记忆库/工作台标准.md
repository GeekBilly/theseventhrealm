# 第七境 · 写作工作台标准（格式与信息架构唯一依据）

> 用户 2026-11-20 拍板。**每次格式改动，必须同步到工作台网站能导航到的每一个页面**，不允许只改一处。本文是这套标准的唯一落点；改动前先读本文，改完按文末检查表逐项验收。
> 适用范围：`01-内容/写作工作台.html` 及其全部可导航页面——主界面 7 个分区 + 文档页（167 篇 md 经统一外壳渲染）。

## 一、最高规则：格式改动 = 全站同步

**用户原话**：「每次我的格式改动都要到所有的子分支，把整个工作台网站能导航到的页面都做一个修改。」

工作台不是单页，而是「一个主界面 + 167 篇文档页」的统一体。任何格式／字号／风格／信息架构改动，都必须同时落到下面三处，**缺一即为未完成**：

| # | 落地位置 | 覆盖页面 | 改什么 |
|---|---|---|---|
| 1 | `11-运营/scripts/写作工作台.template.html` | 主界面（7 个 Tab 分区） | CSS（字号/风格/布局）＋ 7 个分区 DOM 结构 |
| 2 | `11-运营/scripts/workbench-core.py` 的 `READER_CSS` | 全部文档页的外壳与正文样式 | 与主界面同一套字号阶梯与风格 |
| 3 | 同文件 `shellDocHTML()` / `reader_js()` | 全部文档页的信息架构 | 总-分-细节外壳、目录、折叠逻辑 |

> 🔴 绝不能在成品 `写作工作台.html` 上直接改布局——它是 rebuild 产物，会被覆盖。改模板 + core，再 rebuild。

### 写入架构：浏览器直写，无常驻服务（2026-11-20 用户拍板）
- **用户诉求**：「把后台任务关了，每次点同步或保存时才提交更改」。已确认浏览器直写可行（内置浏览器与 Chrome 的 file:// 下 `showDirectoryPicker` / `FileSystemWritableFileStream` 均可用且为安全上下文），据此**废弃常驻 8899 服务**作为日常写入方式。
- **日常流程**：双击 `01-内容/启动写作工作台.command` → Chrome 打开 `写作工作台.html`（**纯 file://，无进程**）→ 点「连接工作目录」授权 `01-内容` 一次 → 编辑点「保存到磁盘」＝浏览器直接写 md；点「同步全库」＝浏览器遍历所有 md、在 JS 里 `mdRender()` 重建内嵌快照并写回 HTML 自身。
- **提交时机**：🔴 **只有点保存／同步时才写盘**，平时网页只读内存快照，不碰磁盘、无常驻进程。
- **落地位置**（第 3 处 `reader_js()` 承担全部写入逻辑）：`connectDir()` 取目录句柄；`readText/writeText` 走 `FileSystemDirectoryHandle`；`mdRender()` 与 Python `render()` 逐条对齐；`saveDoc()` 写单个 md + `rebuildFromDisk()`；`syncAll()` 遍历重建。
- 🔴 **JS 里禁止字面 `</script>`**：会出现在脚本源码中导致 HTML 提前闭合、整段脚本失效（曾踩坑）。用 `'<'+'/script>'` 拼接构造（见 `rebuildHTML()`）。
- `serve --port 8899` 保留为**兼容备用**，默认不启动；`rebuild` 命令仍用于"改模板后重建成品"。

## 二、三级字号阶梯（全站写死，依次递减、差距不悬殊）

| 层级 | 用途 | 字号 | 字重 |
|---|---|---|---|
| **总** | 区标题 `h2`、文档标题 `.dvhead` | **22px** | 600 |
| **分** | 分组 `summary`、本档目录 `.dvtoc .cap` | **18px** | 600 |
| **细节** | 正文、条目、目录项、表单项 | **16px** | 400/600 |
| 辅助 | 定位、状态、导语、页脚、元信息 | **14px** | 400 |

- 三级差距 4px/2px，**不往下掉到 11–13px**（旧的缩小字号作废）。
- 辅助信息是附注，不计入三级；但仍用 14px，保证可读。
- 文档正文内 `h1/h2` 归「分」18px、`h3/h4` 归「细节」16px，不另起字号。

## 三、风格规范（操作台面板 · 收敛为一套，不许叠花样）

> 🔴 **审美方向（2026-11-20 用户拍板更新）**：从早期「纯白底＋细横线、文字裸露」改为 **「操作台面板」**——每个功能区是一块有边界的独立面板，文字一律收进面板内，像产品控制台。早期"去卡片化/文字裸露"口径**作废**，以下为新标准。

- **字体**：全站宋体 `--f:'Noto Serif SC','Songti SC','STSong','SimSun',serif`；靠字重分层，不靠换字体。
- **底色层次**：页面底用纸色 `--paper:#f6f4ef`；所有内容收进白色面板 `--white`，用 `--hair / --hair2` 细边框 + `--r:3px` 圆角 + 极淡投影勾边。文字不裸露在纸底上。
- **颜色**：墨色 `--ink:#1a1a18` 正文、次级 `--ink2:#6b675f`、朱砂 `--cinnabar:#b03826` 点睛。朱砂只用于：当前 Tab 标签、区标题下双线、卡片顶边、跳转链接、折叠符号、聚焦边框。
- **面板层级（每块都有边界）**：
  1. Tab = 一条带边框的导航条，选中项朱砂描边＋浅朱砂底；
  2. 服务状态 = 一条带边框的状态条；
  3. 分区 = 一块大白面板，区标题下朱砂双线；
  4. 分组/折叠 = 独立小面板，浅灰标题栏（`-` 符号在左、附注 `.sm` 在右）＋白底正文；
  5. 入口卡片 / 年代行 / 校验项 / 表单域 / 输出框 = 各自有细边框的小块。
- **明令禁用**（勿引入）：数字徽章、胶囊状态标签、圆点时间轴、大面积灰底铺陈（浅灰 `--ghost` 仅用于面板标题栏与派生台流程区，不铺满整页）。
- 折叠符号统一 `＋／－`；展开/收起、跨区跳转沿用 `data-fold` / `data-gotab` / `data-dvfold`。
- **文档页同款**：`.dvwrap` 主面板 → `.dvtoc` 目录子面板 → 各 `.dvsec` 折叠面板；正文样式阶梯与主界面完全一致。

### 动效规范（丝滑 · 微炫 · 简单优雅，全站同款）
- **原则**：只用 `transform / opacity / box-shadow / text-shadow` 过渡，**不引入新颜色、不改布局位移**；克制，不做粒子/渐变流动/大幅位移动画。
- **令牌**：`--ease:cubic-bezier(.22,.61,.36,1)`、`--dur:.28s`，写在模板 `:root`；core.py 文档页用同名变量并带 fallback（两处独立可生效）。
- **四组动效**（主界面模板 + core.py `READER_CSS` 各写一份）：
  1. 面板入场 `@keyframes panelIn`：opacity 0→1 + `translateY(10px→0)`，`.42s`，作用于 `section.tabpane`（Tab 切换 display:none→block 自动重放）与文档页 `.dvwrap`。
  2. 折叠正文 `@keyframes foldIn`：`.3s`，作用于 `details.fold[open] .fbody` 与 `details.dvsec[open] .sc`。
  3. 微浮 hover：`.cell/.hero-card/.row` 抬 2px + 柔光；`.tabbar label/.rbtn/button` 抬 1px；`.dvtoc li` 右移 2px。
  4. 状态点呼吸 `@keyframes breathe`：`#svcStatus.on` 绿点柔光 `2.6s` 缓慢明灭。
- 所有可交互元素（label/btn/cell/row/summary/表单域等）统一 `transition`，走 `--ease/--dur`。
- 🔴 **必须有** `@media(prefers-reduced-motion:reduce)`：系统要求减少动效时全部 `animation/transition:none`。
- 改动仍遵第一节全站同步：模板动效块 + core.py `READER_CSS` 两处都要写，缺一即文档页与主界面不同步。

## 四、信息架构：总—分—细节（每个页面一致）

1. **总**：区标题 + **一句话**描述（`.desc`，讲清「这是什么模块」）+ 一行定位（`.loc`，年代起止 + 当前状态）。
2. **分**：分组标题即 `summary`，点开才看细节；**不再另铺一层目录索引**（旧的 `.idx/.subcap` 索引层已删除，避免与折叠层重复）。
3. **细节**：分组内的具体内容；跨分区重复的只写跳转引用（`data-gotab`），不复制正文。

- 文档页由 `shellDocHTML()` 自动套同一外壳：信息条 + 大标题 + 导语（取首个 blockquote）+ 本档目录 + 折叠分节。
- 🔴 目录分段用统一 `flush()`：遇 `h2/h3` 先结算上一段再开新段，**同名标题不得重复出现**（曾因重复 push 导致总纲目录 31 节，修复后 21 节）。

## 五、布局规则（一行不堆太多）

- Tab 允许 `flex-wrap` 换行，7 个标签不硬挤一行。
- 卡片一行最多 2 个（`.pair` = `repeat(2,1fr)`，窄屏降 1 列）。
- 派生台表单、校验正文、文档目录均单列。
- 源流链用一行文字链 `.chain`，不铺多张卡片横排。
- 年代骨架列表 `.row`：序号 / 名称+年代 / 状态，一组一行。

| 史实 | 119 事件节点、263 条引文 |
| 源流链 | 史实→总纲→小说→漫画／动画→电影，流不倒灌源 |

> 改格式时**不得顺手改内容口径**；如发现内容与总纲冲突，单独提出、经用户裁决再改。
