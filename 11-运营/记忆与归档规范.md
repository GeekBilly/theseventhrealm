# 记忆写入与归档规范（v1 · 2026-09-30）

> 解决一件事：`MEMORY.md` 每次会话都会被整段注入上下文，**太长就会被截断**——一旦截断，后面写着什么我根本看不见，等于白记。
> 所以必须立标准：什么有资格留下，其余的一律挪到分支目录，每天自动挪。

---

## 一、一句话判断标准

> **这条信息，三个月后我新开一个会话、只拿到 `MEMORY.md`，就必须知道吗？**

- **是** → 留下（且尽量压到一两句）
- **否**（有更好的地方放 / 上下文不带也能干活 / 只是过程记录） → 挪走

第二刀：**删掉之后我会不会犯同一个错？** 会 → 留下（这是硬约束）；不会 → 挪走。

## 二、三级分类

| 级别 | 内容 | 处置 |

## 四、 tidy 指令（给脚本看的标签）

在 `## ` 标题行**下一行**写注释，Markdown 渲染时不可见，脚本可读：

```
## G. 市场与客群
<!-- tidy: rank=p2 | move-to=04-市场/长期结论.md | pointer=客群三层与定价详见 04-市场/长期结论.md -->
```

- `rank`：`p0` / `p1` / `p2` —— **脚本只会自动搬 p2**
- `move-to`：归档目标文件（仓库相对路径）
- `pointer`：搬走后原地留下的那一行（**必须写清楚去哪了**，否则等于失联）
- 没有 tidy 指令的节：**默认当作 p1，不会被自动搬**（保守起见）

## 五、预算规则（2026-10-02 改为**随项目规模动态计算**）

### 5.1 为什么不再用固定值

固定 8000 有两个毛病：项目小时太宽（白付每次会话的固定开销），项目大时又没依据说该不该涨。**改成跟着规模算。**

### 5.2 公式

```
预算 = 4000 + 200 × 活跃域数 + 100 × 规范文档数
区间 = [5000, 12000]
```

- **活跃域** = 文件数 ≥5 的顶层目录 → **每个域约 2 条常驻约束（≈200 字符）**
- **规范文档** = 文件名含 `README/手册/规范/流程/规则/总原则/约定/指南/SOP` 的 `.md` → **每份约 1 行指针（≈100 字符）**
- **基础 4000 不随规模变** —— 总原则指针、协作规范、凭据位置就那么多

**为什么用「域数 + 规范文档数」而不是文件数** —— 用户最初的想法是按文件夹/文件数缩放，但实测**文件数是坏指标**：`02-商品` 有 488 个文件，不等于有 488 条规矩。真正决定"必须常驻多少"的是：

- **多一个功能域 → 多一组必须常驻的约束**（域级指针）
- **多一份规范文档 → 多一行必须留的指针**

**为什么有硬顶 12000** —— 记忆每次会话全量注入，超长会被截断，**截断后等于白记**（这是本规范立规的原始理由）。超过 12000 的部分必须靠「下沉 + 指针」消化，**不许涨预算**。

> ⚠️ **一次真实的校准记录（2026-10-02）**：第一版系数定得过紧（`4000 + 150×(域−6) + 50×(规范−8)` = 5200），
> 实测发现**压缩掉所有可下沉的 P2 之后，仍有约 7700 字符是真实 P0/P1 约束**（商标判例、版式禁令、bash 陷阱、R-19 纪律……）。
> 若强行压到 5200，只能动 P0 —— **那等于用「成本」去换「风险」，违反 `风险 > 成本` 的优先级**。
> ⇒ **系数按实测底线校准为上式**。教训：**系数不能拍脑袋，要先量真实内容再定。**

### 5.3 效率指标（比总量更能说明问题）

| 指标 | 目标 | 含义 |
|---|---|---|
| **记忆密度** ＝ MEMORY 字符 ÷ 规范文档数 | **≤ 250** | 每份规范摊到多少常驻字符；超了说明**细节没下沉** |
| **记忆占比** ＝ MEMORY 字符 ÷ 全部 md 字符 | **≤ 0.60%** | 常驻 vs 沉淀的比例 |

### 5.5 怎么用

```bash
python3 11-运营/scripts/memory-tidy.py --check                 # 自动算预算 + 效率指标
python3 11-运营/scripts/memory-tidy.py --apply                 # 超预算才动手（只搬 p2）
python3 11-运营/scripts/memory-tidy.py --check --budget 8000   # 手动覆盖（应急）
```

**搬运规则**（沿用）：

1. 低于预算 → `--apply` 什么都不做。
2. 超预算 → 按 **p2 节从大到小**依次搬，直到回到预算内。
3. 搬运是**追加**（目标文件加一段 `## <日期> 归档自 MEMORY.md`），**不覆盖**；原地留 `pointer` 行。
4. 搬前写 `MEMORY.md.bak`；留痕到 `11-运营/reports/记忆整理-<日期>.md`。
5. **p0 / p1 永不自动搬**，超预算只报警。

> ### ⚠️ 当前最大的问题：**tidy 指令一条都没写**
> `--apply` 只搬「同时有 `rank=p2` 和 `move-to`」的节。**实测全部 11 个节都是 `p1`（默认值）** → 脚本永远不会动手。
> **要让瘦身真的发生，必须先给够格的节补 `tidy` 指令**（格式见 §四）。

## 六、红线

- **不得把 p0 内容自动搬走**（包括"为了降体积"的理由）。
- **不得删除任何记忆内容**，只能移动 + 留指针。
- **凭据的值永远不进记忆正文**，只写"在哪、怎么取"。
- 每次我写记忆时，先问一句：**这条符合上面三级的哪一级？** 拿不准就写进当日流水，别塞长期记忆。
