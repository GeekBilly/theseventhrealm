# 第七境 · 作品范式（2026-10-03 定）

> **一句话**：**框架固定、只换内容** —— 每张作品的七个区位、各区位放什么，全站统一；
> 每期只换「字 / 金句 / 年代 / 底纹」四样内容，其余（品牌名、印章、网址）**一个字都不动**。
>
> **范围**：所有「第七境」壁纸级作品（A 线字体演变、B 线姓氏源流，以及后续任何新线）。
> **不适用**：手机竖版（另立，见 §六）、网页/长图（非单幅作品）。

> ⭐ **母版原则（2026-10-03 用户指令，优先级最高）**：
> **商/周 v9 壁纸 = 母版**。⚠️ **母版文件是这两份**（2026-10-03 更正）：
> `03-字形线/版式/模板-朝代-v9.html`（＝商 v9 ＋ 商品化补丁，合并版；std）
> 与 `05-承接站/样张/shang-v9-std.html`（同内容的参照成品）。
> 此前文档写的 `wallpaper-商-v9.html` **不含**商品要素（系列标与 ™），拿它比对会漏项 —— 已更正。
> 其余所有产品「只是把商周壁纸的**字**和**底纹**做了一次替换」——
> 版式的**位置、大小、字体、字距、图层**一律照抄，**不许自己发挥**。
> 落款两区（⑤ 左下竖排名+朱砂点+印、⑥ 正下中品牌行+网址）**逐像素照抄**商/周 v9
> （`.colophon` L79–87、`.brand-block` L89–94）；改这两区＝改范式＝**C 档**。
> ⭐ **唯一允许偏离母版的地方**：两区**整体下移 40px**（`bottom` 140 → 100，2026-10-03 用户指令
> "落款往下来点"）；除 `bottom` 外，字号、字距、图源、图层、相对关系**一律不动**。

## 一、为什么要有范式

三条理由，按重要性排序：

1. **识别度靠"不变"建立**：观众记住的不是某一张，而是"又是这张的版式"。
   框架一变，看十张也认不出是一家的。
2. **产能靠"只换内容"提升**：固定件（品牌名、印章、网址）零成本复用；
   变量件（字、金句、年代、底纹）才需要每期投入。
3. **验收靠"坐标"判定**：固定区位有确定坐标，可脚本量取，不靠眼感。

⚠️ **换范式的代价**：范式是所有作品的公共骨架，**改一次＝已交付的全部作品都要重渲染**。
所以改动按 **C 档**走（见 `../11-运营/每日上线评审流程.md`），必须写执行申请单。

## 三、底纹规则（硬约束）

> **底纹永远在右侧** —— 右上、右中、右下皆可，**永不进左半幅**。

**为什么**：左侧是"文字区"（①系列标、⑤落款），中部是主体字；底纹放左侧会直接压字、
让文字失去清晰的落脚点。右侧天生是留白，底纹在那里最稳。

**B 线现行参数**（`gen-surname-figure.py --layout paradigm`）：

```css
/* v3（2026-10-03 用户定）：整幅进画 —— 不裁、不渐隐 */
.figure{right:0;bottom:0;height:1000px;opacity:.215}
```

四条要点：
1. **底纹素材必须是带 alpha 的墨迹层**，不能用白底图 —— 白底图会以一个淡灰矩形的身份显形
   （两个坑的完整复盘见 `商品线操作手册.md`「姓氏线 · 人物底纹」）。
2. ⭐ **人物整幅进画，不许裁、不许渐隐**（v2 的 `bottom:-40` + `to-top` 渐隐会把人物下半身
   吃掉，用户明确否决）。判据：`.figure` 的 `left ≥ 900 / top ≥ 0 / bottom ≤ 1080 / right ≤ 1920`，
   且**素材墨迹 bbox 完全落在画面内**。若素材本身在边缘被切断（如半身像），
   **只能重生图**，不能用渐隐"藏"起来。
3. ⭐ **浓度基准（2026-10-04 更正）**：B 线 `.figure{opacity:.32}`、A 线 `.texture{opacity:.32}`
   —— **两线同为 .32**。⚠️ 旧写的「`.215` 是两线统一的版式值」是**错的**：A 线一直是 .32，
   B 线的 .215 是历史遗留，物理上限墨深只有 0.193（A 线实测到 0.322），
   这才是「B 线淡且闷」的根因。判断标准＝**第四格（最靠右那格字）的笔画仍然一眼可辨**。
   底纹太浓会与主体字争夺注意力，太淡则白花钱生图。
   ⭐ **量化判据（2026-10-04 起）**：底纹框内 `<250` 灰度像素占 **16%–19%**。
   低于 16% 视为糊（赵的生图原样只有 12.9%），高于 19% 开始抢主体。
   ⚠️ `<250` 只反映**覆盖面积**，提浓时几乎不动（赵 1.6→2.0 仅 +0.9pp）；
   **浓淡要看 `<235`**（赵 2.0× ≈ 12.5%）；`<200` 恒定不动（最浓处已被 alpha=255 封顶）。
   ⚠️ **"看不清"优先在素材层调（`--density K` / `--haze K`）**；`.32` 与素材参数是一套
   标定，动一个就要重新标定整套。
   ⭐ **风格对齐（与 A 线玄鸟/凤凰同呼吸）**：判据是**纯底纹层的墨深分布**
   （渲染时其它元素 `visibility:hidden`，`d=(255−灰度)/255`）。
   A 线＝「大片极淡雾 + 少量浓纹」（中位 .043–.075 / p90 .31+ / 最浓 .322）；
   B 线改前＝「一小块均匀中灰」（中位 .125 / IQR .118）。改 `.32` + `--haze .45 σ80`
   后中位 **.078 / IQR .165 / 最浓 .290**，节奏与 A 线吻合。
   ⚠️ 加雾后 **`<250` 覆盖率判据失效**（雾极淡会被全算进去），一律以墨深分布为准。
   **赵定档 `--density 2.0`**（1.6 偏淡、2.2 已到边际递减）。
   ⚠️ 框的左界 = `1920 − 素材宽/素材高 × 1000`（**随素材宽高比变化**，别照抄数字）。
   完整标定流程见 `06-姓氏线/底纹-人物/README.md`。
4. **要往左放**：底纹主体压在**中线右侧**（`left ≈ 940`），左缘可略过中线，
   **但不得进左半幅的文字区**（①系列标、⑤落款区必须与底纹零重叠 —— 已实测：⑤区重叠 0%）。

⚠️ **A 线现状待改**：商/周壁纸的底纹（玄鸟/凤凰）目前是**整幅居中 + 椭圆径向 mask**，
不符合"永远在右侧"。改法是保留素材，把 mask 改成右侧渐隐、位置推到右半幅（本轮未改，见 §七）。

### 母版没有的元素，一律去掉（2026-10-03 用户指令）

> ⭐ **判据一句话**：**先 grep 母版**（`wallpaper-商-v9.html` + 商品化补丁 `gen-wallpaper-classic.py`），
> 母版里没有的元素，B 线一律 `display:none` —— **不是调整位置，是删掉**。
> 用户原话：「只是把商周壁纸的**字**和**底纹**做了一个替换，所有的版式设计都不要动」。

| 项 | 规则 | 说明 |
|---|---|---|
| **纸底** | ⭐ **纯白 `#ffffff`** | 母版 `--white:#ffffff`。B 线原用米色 `#f7f5f0`，**显黄**（用户指出），已改纯白 |
| **底部山水** | ⭐ **不要** | 远山 `.mountains` 与山雾 `.mist` 一并 `display:none`（B 线原有一套，用户要求去掉）|
| **画心细横线** | ⭐ **不要** | `.rule`（四联字下方 `width:900 height:1px` 的灰线）。**母版 grep「rule」0 命中** |
| **四周细边框** | ⭐ **不要** | `.frame`（`left:64 top:56 right:64 bottom:56` ＋ `border:1px solid rgba(26,26,24,.10)`）。用户口中的"左右两条灰线"就是它的左右边。**母版 grep「frame」0 命中** |
| **格间竖线** | ⚠️ **A 线有、B 线无** | A 线 `.divider`（`width:1px height:200px background:#ded7c9`）是三格之间的分隔线，**母版有**；B 线四格目前没做（未做不算错，要加则按母版规格）|

**踩过的坑**：这两条灰线是 B 线模板自带的老装饰，一直没人动过 ——
用户换上 Mac 桌面壁纸后**第一眼就看出来了**（"四联字下边多了一条灰线，还有左右两条"）。
教训：**"多余元素"比"位置不对"更显眼**，每次改版都该把成品和母版叠一次像素差。

判据（可脚本量）：空白处取样应为 `(255,255,255)`；底部带（y 1010–1080、x 0–600）均值应 ≈ 255；
**画面最左/最右列（x=64/65、1855/1856）在 y 100–1000 区间应为纯白**（灰线一旦存在，这里会出现连续非白像素）。
**发黄自查**：整图 `R − B` 差值应 < 1（实测 0.16–0.38）—— 差值大即纸底或墨色偏暖。

A/B 两线乃至后续任何新线都直接复制商/周 v9 的 CSS，**不重新调数值**。

### ② 右上角"金句"的写法（两线共用）

- **金句**：毛笔体（`msz`）竖排，⭐ **`font-size:54px` / 行距 46**（照抄商/周 v9）；
- **出处**：宋体竖排小字，⭐ **`font-size:20px` / 行距 16**，放在金句**左侧**（更靠画面内侧）；
- 出处格式：⭐ **一列、圆点隔开**：`《书名》朝代·第一句`
  （⚠️ 竖排里 **`<br>` 会另起一列**，两列看着散 —— 用户 2026-10-03 要求「和百家姓放在一列用一个圆点隔开」；
   句序用**中文数字**；古籍引文按 `42` 条口径：**不猜、写不出原文就写"未能确认"**）。

⚠️⚠️ **两列必须留出水平间隙 ≥ 24px**（2026-10-03 踩坑：放大字号后出处直接压在金句上）：
竖排元素的**盒子宽度 = 字号 × line-height**（金句 54×1.7 ≈ 92px），比字的墨迹宽得多，
肉眼看着"还早"，其实已经重叠 —— 判据只能靠量：
`金句.left − 出处.right ≥ 24`。实测修后：金句 `x1710–1802`、出处 `x1638–1680`，间隙 **30px**。

⚠️⚠️ **出处列绝不能压到主体字**（2026-10-03 实测踩坑）：B 线四格字区若用原 `gap:104px`，
总宽 1488px、右缘 **x1718**，直接吞掉出处列（x1638–1680）；
商周三联字区只 915px 所以从没暴露这个问题。
→ **四格字区的格间距必须按字幅比收窄**（`gap:104 → 38`，竖断线另留 `margin:0 18px`），
收窄后字区 ≈1267px、右缘 **x1574**，与出处列留 **64px** 间隙。

### ③ 主体字区的排法（2026-10-03 用户定）

1. **右起展卷**：屏幕自左向右 = `碑刻 | 隶书 | 行书 | 草书`，展卷自右向左读 = **草书 → 行书 → 隶书 → 碑刻**。
   副标题相应写 `右 起 展 卷 · 自 草 书 至 碑 刻`。
   （⚠️ v7 曾把三联式「古在右」套到四联上，用户 2026-10-03 更正为「按草书到碑刻，从右往左」。
   想反过来只需把 `gen-surname-v2a.py` 的 `ORDER4` 换成 `reversed(ORDER4)` 并同步副标题。）
2. **格间竖断线**：照抄母版 `.divider`（`1px × 200px`，`#ded7c9`，`margin-bottom:48px`），
   按字幅比 `232/262 = 0.886` 缩放 → **`1px × 178px`，`margin-bottom:42px`**，另加左右 `18px`。
   ⚠️ **必须写成三值 `margin:0 18px 42px`**：写成两值 `margin:0 18px` 会把下边距冲成 0，
   竖线掉到字区底边（用户 2026-10-03 指出"割线偏下"就是这个）。
   ⚠️ 商周**没有** `.rule`（字下横线）和 `.frame`（四周边框），B 线已删干净，别再手滑加回来。
3. **垂直居中**：字块（大字 ＋ 字下标签）的**中心 = 画面中心 540**（母版 `.triple` 中心 540）。
   实测 `.quat` `t390 b690`，中心 540 ✅。

### 字体：必须与母版**同源**（2026-10-03 查明）

| 用途 | 写法 | 说明 |
|---|---|---|
| 金句 / 落款「第七境」 | ⭐ `font-family:var(--f-brush)`，变量值 **`'msz','Ma Shan Zheng Local','Ma Shan Zheng','KaiTi',serif`** | **文件版排链首** |

⚠️ **两件事必须记住**：
1. 商/周 v9 写的是 `'Ma Shan Zheng Local','Ma Shan Zheng','KaiTi',serif` ——
   **这三个字体本机一个都没装**，是生成商周那台环境装过；本机直接照抄会一路回退成宋体/黑体，**反而不像母版**。
   所以 B 线把项目字体文件 `msz`（`MaShanZheng.ttf`）放链首，才能稳定复现母版字形
   （实测落款「第七境」与母版成品 IoU **0.826**、骨架 3px 覆盖率 **1.000**）。
2. B 线 `@font-face` 把 **`serif` 这个通用族名**定义成了 `NotoSerifSC-Black` ——
   于是任何字体链末尾的 `serif` 都被它抢占，回退会落到**比母版粗一倍的黑体**。

## 九、⭐ 版式权威文件与工作流程（2026-10-03 用户要求："信息集中在尽量少的文件里"）

### 9.1 版式只有一个出处：两个模板 HTML

|---|---|---|---|

**规矩**：
- 模板里**只有字面量**：位置 / 字号 / 字距 / 颜色 全部写死并带注释说明来由（引用母版值或缩放算式）。

  残余文字被当正文渲染 → 整幅下移。2026-10-03 在 B 线模板上踩过，症状是所有元素一起下移 46px）。

### 9.2 生成器只做两件事

- `06-姓氏线/版式/gen-surname-v2a.py` —— 数据 + **字形覆盖闸门** + **槽位替换**（`fill()`）。
  **不持有任何版式数值**；改版式只改模板。
- `06-姓氏线/版式/gen-surname-figure.py` —— 底纹素材处理（`--prep`）+ 渲染出图。
  **同样不持有版式数值**，另提供 `--sync-mac` 由 std 模板同步出 Mac 模板。
- 槽位写法：模板里用注释对 `S:槽名` … `E:槽名`；槽名 = tag/title/verse/src/quat/meta（B 线）
  或 tag/title/triple/quote/texture/brand/era（A 线）。

### 9.3 渲染流程（唯一一条写不进 HTML 的规矩）

**必须 2× 渲染再 LANCZOS 缩回**，不能直渲 1×：

```
1920×1080 版式 → --force-device-scale-factor=2 → 3840×2160 → LANCZOS → 1920×1080
1920×1248 版式 → 同上                         → 3840×2496（Mac 档直接留这一张）
```

依据：**商/周成品 std 图本身就是 4K 缩制品**（`shang-v9-std.png` 与
「`shang-v9-std-4k.png` 缩回 1920」差异 mean **0.59**、墨量完全相同）。
直渲 1× 的笔画会比母版细一档 —— 这就是 v7 记录里那条「已知未达标项」的解法。

### 9.4 出任何问题先看哪三处

1. **模板 HTML** —— 版式对不对、槽位有没有被改坏；
2. **工作流程（本节 9.3）** —— 是不是走了 2× 再缩；
3. **`measure-paradigm-align.py`** —— 拿母版 `shang-v9-std.html` 当基准逐项比 l/r/t/b/w/h/fs/ls。
