# 商店页架构设计方案（2026-10-03）

> **用户要求**：把藏品页重新规划，做成一个 shop 页；朝代（朝代壁纸）、人物（百家姓人物壁纸）、典集（将来）各有商品专栏；**文章里出现相关商品时放跳转链接**。
> **核心判断**：你要的其实不是"一个商店页"，而是**内容与商品的双向通道**。这份方案围绕这条来设计。

---

## 一、先说现在的问题

```
站点现状
  /collection/        一页装完：金句线 + 字体演变 + 表单 + 怎么拿到
  /5000years/<朝代>/   16 个朝代页，每页几千字正文 —— 但【没有一个字提到商品】
  /shop 或分类页        不存在

产品现状（5 条线）
  金句线·手机竖版   16 朝   免费（引流）
  金句线·桌面横版   16 朝   未上架
  A 线 字体演变     商/周   未上架
  B 线 姓氏源流     100 姓  未上架（待人物底纹）
  典集                      未做
```

**⇒ 两个断层**：

```
① 有人读完了「唐朝」那页 5000 字 —— 然后呢？没有任何去处
② 有人想看有什么可买 —— 只有一页，且分不清哪条线是哪个
```

**⇒ 这两个断层，就是这份方案要接上的。**

---

## 二、整体结构：三层 + 双向链接

```
【内容层】                    【商品层】
/5000years/tang/  ←──────→  /collection/dynasty/tang/
 唐朝正文 5000 字              唐朝壁纸商品栏
      │                              │
      │  ① 正文末尾「相关藏品」        │  ② 商品页「这个朝代我们写了 5000 字」
      └──────────────────────────────┘
              双向链接 = 转化通道
```

### 商品层三层结构

```
L1  /collection/              商店首页
      三条线并列：朝代 · 人物 · 典集
      每线一张大卡（含代表图 + 已上架数量 + 入口）

L2  /collection/dynasty/      朝代专栏（总览 16 朝）
    /collection/surname/      人物专栏（总览 100 姓，可分页/搜索）
    /collection/books/        典集专栏（将来）

L3  /collection/dynasty/tang/    单朝商品栏 ← 与 /5000years/tang/ 成对
    /collection/surname/zhao/    单姓商品栏 ← 与人物名单成对
```

⚠️ **沿用 `/collection/` 不改 URL** —— 避免已发出去的链接失效（知乎那篇的链接就指着站点）。

## 四、⭐ 双向链接（这是方案的核心）

### 方向一：文章 → 商品

**站内（16 个朝代页）** —— 在**每篇正文末尾**加一个区块：

```
┌──────────────────────────────────────┐
│ 相关藏品                                    │
│                                          │
│ [图] 唐朝 · 桌面横版壁纸                     │
│      单朝 ¥12 ｜ 即将开售                   │
│      [通知我]        [看看十六朝 →]         │
└──────────────────────────────────────┘
```

**放几条？** —— **最多 2 条** ✅ 理由：
```
· 手机上一屏能看完
· 多于 2 条就变成广告位，读者会烦
· 一条是"这个朝代"，一条是"全套"
```

**站外（知乎、公众号）** —— 一篇只放 **1 个链接** ✅
```
不要链到首页（人都散掉了）
链到【与该文最相关的那个商品专栏】
  例：黑夫与惊那篇（秦朝）→ /collection/dynasty/qin/
```

### 方向二：商品 → 文章

**每个商品页里**都放一条反向入口 ✅：
```
这个朝代，我们写了 5000 字
[读《唐朝》长卷 →] /5000years/tang/
```

**为什么这条同样重要**：
```
① 它让商品页不只是一张价目表 —— 有内容托底，才显得"这个牌子是认真做的"
② 读完长卷的人更容易下单（信任先于购买）
③ 也是 SEO 的内链
```

## 五、⚠️ 关键设计：**状态感知**

产品线现在**大多没上架** ✅ 如果不处理，文章里的链接会指向空页 ✅

**⇒ 四个状态，同一套结构，只换按钮**：

| 状态 | 页面显示 | 按钮 |
|---|---|---|
| **未做** | 不出现 | — |
| **在做** | 「正在准备中」 | 无（或「想看？留个邮箱」） |
| **即将开售** | 显示价格 + 首发时间 | **【即将开售 · 通知我】** → 锚到表单 |
| **已开售** | 显示价格 | **【立即购买】** → 面包多Pay 链接 |

**⇒ 核心：开售那天只换按钮文案和链接，页面结构一个字不动** ✅
（这条沿用我们之前定的"先放通知、开售换购买"原则 ✅）

**⇒ 于是文章里的链接**：**发布时写一次，永久有效** ✅ —— 这是这个设计最省事的地方 ✅

## 六、URL 与命名

```
/collection/                 商店首页（不改，避免断链）
/collection/dynasty/         朝代专栏
/collection/dynasty/<slug>/  单朝   slug 沿用 /5000years/ 的（shang zhou qin han…）
/collection/surname/         人物专栏
/collection/surname/<slug>/  单姓   slug 用拼音（zhao qian sun…）
/collection/books/           典集专栏
```

⚠️ **单姓 slug 用拼音**（`/surname/zhao/`）而不是汉字 —— 汉字 URL 在分享时会被编码成一长串，很难看，也容易在贴链接时出错。
