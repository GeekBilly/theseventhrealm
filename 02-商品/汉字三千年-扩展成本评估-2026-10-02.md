## 三、Token 估算

| 工作 | 估算 | 说明 |
|---|---|---|
| 把商/周模板**参数化成生成器** | **12–18K** | 商/周 两版式仅差 **44 字符** → 高度同构，容易；可照抄金句线生成器的写法 |
| 调出第一朝（隋） | **4–7K** | 三联比例 + 第③格从 img 换成字体渲染 |
| 批量出 6–7 朝 | **≈ 0** | 生成器跑 + 本地 Chrome 渲染，**不花 token** |
| **小计（不含篆隶）** | **≈ 16–25K** | |
| 篆隶字体调研（1 个 agent） | **8–15K** | 查 OFL / 可商用授权的篆书·隶书 |
| 若找到，加秦汉 | **3–5K** | |
| **合计** | **≈ 25–45K** | |

**判断**：若只做 **6–7 朝**，成本 **≈16–25K**。
换来的是「汉字三千年」从 **2 朝（6 张）→ 7 朝（约 21 张）**，是一个**真正能撑住 B 档定价**的成套产品。**划算。**

## 四、但更划算的可能是：百家姓

用户提议的方向 —— **实测证据支持它**。

### 4.1 技术关已过（今天实测）

48 字样本（常用姓 + 故意混入的生僻姓）：

| 字体 | 缺字数 |
|---|---|
| `NotoSerifSC-Black`（子集） | 3 / 48（邴 仉 郐） |
| **马善政毛笔** | **0 / 48** ✅ |
| **龙藏** | **0 / 48** ✅ |
| **挚芒行** | **0 / 48** ✅ |
| **柳建毛草** | **0 / 48** ✅ |

> **4 个毛笔字体对生僻姓全覆盖**，而毛笔字正是设计的视觉主力。

### 4.2 为什么它可能比朝代更好

| 维度 | 朝代 | **百家姓** |
|---|---|---|
| 内容规模 | 16（能做的 6–7） | **504 姓**（单姓 444 + 复姓 60） |
| 古文字瓶颈 | ❌ 卡死 | ✅ **不需要**（姓氏不必追甲骨文） |
| 定制性 | 无 | ✅ **人人有姓 → 可定制** |
| 客单价潜力 | B 档 ¥12–129 | ✅ **C 档可期**（定制 + 姓氏文化/郡望/堂号） |
| 覆盖面 | 泛历史爱好者 | **前 100 姓≈覆盖 85% 人口** |
| 与小程序「工具」类目的契合 | 弱 | ✅✅ **「输入姓氏→生成壁纸」＝真工具**，正好对上个人主体可开放的「工具-图片处理」 |

### 4.3 需要先确认的三件事

1. **姓氏表准确性** —— 已派 agent 从多来源交叉验证（进行中）
2. **郡望/堂号数据的来源与准确性** —— 这是考据型内容（P2 客群），**错了会砸口碑**，需权威来源
3. **复姓（2 字）的版式** —— 和"多字朝代"同一个排版问题，需单独设计

## 五、我的建议（两条路对比）

| 方案 | 成本 | 产出 | 适合 |
|---|---|---|---|
| **A. 朝代扩展到 6–7 朝** | **16–25K** | 汉字的"三千年演变"完整叙事 | 强化现有字形线 SKU |
| **B. 百家姓** | **≈ 15–25K**（生成器 + 首批） | **504 姓 × 可定制** | ⭐ **规模化 + 可定制 + 对上小程序工具类目** |
| **A+B** | ≈ 35–45K | 两条产品线 | 若都想做 |

> **我倾向 B 先行**：它一次解决三个问题 —— 内容规模、古文字瓶颈、小程序"工具"类目形态。
> 而 A 的价值在于**叙事**（三千年），适合作为 B 之后的第二个系列，或作为 B 的"高端版"。
